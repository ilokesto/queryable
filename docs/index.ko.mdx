# Queryable

버전 **0.0.1**, 비공개 베타입니다. npm에 배포하지 않았으며 로컬 문서는 `next` 채널만 제공합니다.

```ts
import { createQueryable, WHERE, SORT, LIMIT, MAP, VALUES } from "@ilokesto/queryable";

const users = createQueryable({
  alice: { name: "Alice", age: 25 },
  bob: { name: "Bob", age: 30 },
  charlie: { name: "Charlie", age: 20 },
});
const names = users[WHERE](user => user.age >= 25)
  [SORT]((a, b) => b.age - a.age)[LIMIT](2)[MAP](user => user.name)[VALUES]();
// ["Bob", "Alice"]
```

## 연산

| 연산 | 결과 |
| --- | --- |
| `[WHERE]((value, key) => boolean)` | 필터 결과; 타입 가드를 받으면 값 타입도 좁힘 |
| `[SORT]((a, b) => number)` | 숫자형 키도 비교 순서를 보장하는 안정 정렬 `QuerySequence` |
| `[MAP]((value, key) => next)` | 키를 유지한 값 변환 |
| `[PICK](...keys)` | 지정한 레코드 키의 값 전체; 없는 키·중복 키는 무시 |
| `[LIMIT](n)` | `slice(0, n)` 의미 |
| `[GROUP_BY]((value, key) => K)` | 즉시 계산한 그룹; 키 리터럴을 보존하는 `Partial<Record<K, ...>>` |
| `[COUNT]()` | 개수 |
| `[FIRST]()` | 첫 값 또는 `undefined` |
| `[VALUES]()` | 순서대로 담은 새 값 배열 |
| `[FIND]((value, key) => boolean)` | 첫 일치 값 또는 `undefined`; 타입 가드 지원 |
| `[SOME]((value, key) => boolean)` | 첫 일치에서 종료하는 boolean 결과 |
| `[ENTRIES]()` | 순서대로 담은 새 `[key, value]` 튜플 배열 |
| `[TO_OBJECT]()` | 쿼리 메서드 없는 일반 객체 |
| `[REDUCE]((acc, value, key) => next, initial)` | 순서대로 누적; 초기값 필수 |
| `[LAZY]()` | 반복 소비 가능한 비메모이제이션 지연 시퀀스 |

## 레코드·시퀀스와 마이그레이션

`createQueryable`은 수정 가능한 `Queryable<T>` 레코드를 반환합니다. 즉시 실행하는 `WHERE`, `MAP`, `PICK`, `LIMIT`은 새 레코드를 만듭니다. `SORT`는 숫자형 키가 다시 정렬되는 문제를 피하도록 `QuerySequence<T>`를 반환하며, 후속 변환도 시퀀스를 유지합니다.

```ts
import { createQueryable, SORT, LIMIT, ENTRIES, TO_OBJECT } from "@ilokesto/queryable";

const sorted = createQueryable({ 1: 10, 2: 20 })[SORT]((a, b) => b - a);
sorted[LIMIT](1)[ENTRIES](); // [["2", 20]]
sorted[TO_OBJECT](); // 일반 객체에서는 숫자 키가 다시 "1", "2" 순서로 열거됨
```

시퀀스 데이터는 `VALUES`·`ENTRIES`·`TO_OBJECT`로 꺼내세요. 직접 키 조회, spread, JSON 직렬화를 데이터 추출 용도로 쓰지 않습니다.

이번 비공개 베타에서 **`SELECT`를 제거하고 `PICK`으로 이름을 변경**했습니다. import와 호출 이름을 바꾸세요. `PICK("alice")`는 값 내부 필드가 아닌 레코드 키를 고릅니다. 필드 추출은 `MAP(user => ({ name: user.name }))`으로 표현합니다. 레코드 PICK의 삽입 순서는 인자 순서지만 숫자 키에는 객체 열거 규칙이 적용됩니다. 시퀀스 PICK은 인자 순서를 그대로 보존합니다.

## 지연 평가 계약

```ts
import { createQueryable, LAZY, WHERE, MAP, LIMIT, VALUES } from "@ilokesto/queryable";

const query = createQueryable({ a: 1, b: 2, c: 3, d: 4 });
const firstEven = query[LAZY]()[WHERE](n => n % 2 === 0)
  [MAP](n => n * 10)[LIMIT](1);
firstEven[VALUES](); // [20]; predicate에는 a와 b만 전달됨
```

- 기본 연산은 호출 즉시 실행합니다. `LAZY` 이후 `WHERE`, `MAP`, `PICK`, `LIMIT`, `SORT`는 소비 시점까지 미룹니다.
- `VALUES`, `ENTRIES`, `TO_OBJECT`, `COUNT`, `REDUCE`, `FIRST`, `FIND`, `SOME`, `GROUP_BY`는 남은 연산을 실행합니다. `FIRST`, `FIND`, `SOME`, 비음수 `LIMIT`은 앞선 순회를 조기 종료합니다. `LIMIT(0)`은 원본도 읽지 않습니다.
- `SORT`, 시퀀스 `PICK`, 유한한 음수 `LIMIT`은 전체 입력이 필요하므로 소비할 때 버퍼링합니다. `GROUP_BY`는 호출 즉시 전체를 읽어 즉시 평가 그룹을 만듭니다. 레코드의 그룹은 레코드, 시퀀스의 그룹은 시퀀스입니다.
- 매번 소비할 때 새로 순회하고 미뤄 둔 콜백을 다시 실행합니다. 캐시는 없습니다. 예외는 소비 시점에 전파되며, 다음 소비는 처음부터 다시 시도합니다.
- 레코드의 지연 뷰는 소비 시점의 **쿼리 레코드**를 읽습니다. 소비 사이에 쿼리를 수정하면 반영됩니다. 생성 전 원본 객체는 이미 얕게 복사했으므로 원본의 속성 교체는 반영되지 않습니다. 정렬된 즉시 평가 시퀀스는 스냅샷이며, 나중에 `LAZY`를 붙여도 이미 실행한 정렬은 다시 실행하지 않습니다.
- 중첩 값은 참조를 공유합니다. 콜백에서 순회 중인 소스 레코드의 키를 추가·삭제하거나 값을 교체하지 마세요. 순회 중 변경에 대한 스냅샷 격리는 제공하지 않습니다.

단일 탐색에는 `FIND`·`SOME`을 쓰세요. 기본 모드의 `WHERE(predicate)[FIRST]()`는 여전히 필터 결과 전체를 먼저 만듭니다.

## 타입과 집계

```ts
import { createQueryable, WHERE, GROUP_BY, REDUCE } from "@ilokesto/queryable";

const mixed = createQueryable<number | string>({ a: 1, b: "two" });
const strings = mixed[WHERE]((value): value is string => typeof value === "string");
// Queryable<string>
const groups = createQueryable({ a: 1, b: 2, c: 3 })
  [GROUP_BY](n => n % 2 ? "odd" : "even");
const oddTotal = groups.odd?.[REDUCE]((sum, n) => sum + n, 0); // 4
```

가능한 그룹 키라도 실제 데이터에는 없을 수 있으므로 optional로 표현합니다. 빈 쿼리의 `REDUCE`는 초기값을 그대로 반환합니다.

## 공통 계약

- 자기 소유의 열거 가능한 문자열 키만 복사합니다. 상속·비열거·Symbol 키는 제외합니다. `__proto__`, `constructor`, `toString`도 일반 데이터 키입니다.
- 생성과 변환은 얕은 복사이며 입력을 변경하지 않습니다.
- `LIMIT`은 소수 절삭, 음수로 뒤쪽 제외, `NaN`은 빈 결과, `Infinity`는 전체라는 `slice` 의미를 유지합니다.
- 메서드는 receiver가 필요합니다. 구조 분해로 떼어 호출하지 마세요. 레코드의 spread·JSON은 데이터만 남기고 메서드는 잃습니다.
- 메서드를 공유하고 동결하지만 특정 메모리 절감률·속도 우위를 보장하지 않습니다.

## selector 정렬과 명시적 선택

```ts
import {
  createQueryable, SORT_BY, MIN_BY, MAX_BY, TOP_K, NTH_BY, RANK_BY, ENTRIES,
} from "@ilokesto/queryable";

const scores = createQueryable({
  alice: { team: "a", score: 8 },
  bob: { team: "a", score: 9 },
  charlie: { team: "b", score: 9 },
});
scores[SORT_BY](
  { select: user => user.team },
  { select: user => user.score, direction: "desc" },
)[ENTRIES](); // bob, alice, charlie
scores[MIN_BY]({ select: user => user.score }); // alice 값
scores[MAX_BY]({ select: user => user.score }); // bob 값: 첫 동점 유지
scores[TOP_K](2, { select: user => user.score, direction: "desc" })[ENTRIES]();
// [["bob", ...], ["charlie", ...]]
scores[NTH_BY](-1, { select: user => user.score }); // charlie 값
scores[RANK_BY]("charlie", { select: user => user.score }); // 2
```

모든 연산은 `select(value, key)`와 선택적 `direction: "asc" | "desc"`(기본 `"asc"`)를 가진 `OrderRule<T>`를 하나 이상 받습니다. 여러 규칙을 사전식으로 비교합니다. `OrderKey`는 `boolean | number | bigint | string | null | undefined`입니다. 오름차순 범주 순서는 **boolean, number, bigint, string, null, undefined**이며 범주 사이에 형 변환하지 않습니다. 범주 안에서는 `false < true`, number·bigint는 숫자 순서, string은 JavaScript UTF-16 사전식 순서(로케일 정렬 아님)입니다. `NaN`은 `Infinity`를 포함한 나머지 number 뒤에 오며 모든 NaN은 동점입니다. `-0`과 `0`도 동점입니다. 내림차순은 nullish 위치를 포함해 키 순서 전체를 뒤집지만, 모든 규칙이 동점이면 어느 방향이든 입력 순서를 유지합니다.

`SORT_BY`와 `TOP_K`는 원래 키를 유지하는 `QuerySequence<T>`를 반환합니다. 숫자 키와 특수 키도 보존합니다. `SORT_BY`는 앞선 규칙이 순서를 결정해도 entry마다 모든 selector를 한 번씩 계산합니다. 키 캐시는 한 번의 소비 동안만 존재하며 지연 소비 간에는 공유하지 않습니다. 즉시 평가 호출은 바로 실행하고 지연 체인은 소비까지 미룬 뒤 현재 쿼리 레코드를 다시 읽고 selector를 다시 실행합니다. 즉시 평가 결과는 entry의 얕은 스냅샷입니다. 원본 레코드나 원본 entry 배열을 제자리 정렬하지 않으며 중첩 값 참조는 공유합니다. 예외는 기존 `SORT`와 같은 즉시/지연 경계에서 원래 객체 그대로 전파합니다. 기존 comparator `SORT`, 반복 `SORT`, `SORT` + `LIMIT`/`FIRST`를 자동 치환하지 않습니다.

`MIN_BY`와 `MAX_BY`는 지연 체인에서도 호출 즉시 소비하는 terminal입니다. 단일 순회에서 최선 entry와 규칙 키만 유지하고 엄격히 개선될 때만 교체하므로 두 극값 모두 첫 동점 값을 반환합니다. 반환값은 entry가 아닌 **값**입니다. 빈 입력은 `undefined`이며 실제로 선택된 undefined 값과 구분되지 않습니다. 키의 존재·위치는 `RANK_BY`, 키와 값은 `TOP_K(...)[ENTRIES]()`로 확인하세요. 방향은 극값에도 적용되므로 내림차순 규칙의 최솟값은 자연 키가 가장 큰 값입니다.

`TOP_K(k, ...rules)`는 최대 K개 후보를 bounded heap으로 유지한 뒤 승자들을 안정 정렬합니다. K가 N 이상이어도 정렬 순서를 보장합니다. K는 비음수 safe integer여야 합니다. `NaN`, 무한대, 소수, 음수, unsafe integer는 지연 소스를 소비하기 전 연산 호출 시 `RangeError`를 던집니다. `-0`은 0이며 K=0은 upstream과 selector를 읽지 않습니다. 양수 K는 뒤에 `FIRST`나 `LIMIT`이 있어도 첫 결과를 내기 전에 전체 upstream을 소비합니다.

`NTH_BY(index, ...rules)`는 같은 정렬의 **0부터 시작하는 안정 ordinal 위치**에 있는 값을 반환합니다. 음수는 뒤에서 셉니다(`-1`은 마지막). 빈 입력·범위 밖은 `undefined`입니다. index는 safe integer여야 하며 잘못된 index는 소비 전에 `RangeError`를 던집니다. `RANK_BY(recordKey, ...rules)`는 해당 키의 0부터 시작하는 안정 ordinal을 반환하고 키가 없으면 `undefined`입니다. 동점도 입력 순서대로 연속된 서로 다른 순위를 받으며 competition/dense rank가 아닙니다. 둘 다 즉시 소비 terminal이며 호출마다 entry당 각 selector를 한 번만 계산합니다.

N개 entry와 R개 규칙에서 `SORT_BY`는 정렬과 O(NR) 키 버퍼를 사용하고 극값은 O(R) 작업 공간을 사용합니다. `TOP_K`는 O(min(K,N)R) 키를 보관하며 비교 비용은 O(N log(min(K,N)) + min(K,N) log(min(K,N)))입니다. `NTH_BY`는 비음수 index에 최대 `index + 1`개, 음수에 최대 `abs(index)`개의 후보를 유지하는 반복형 heap을 사용하여 재귀 분할 문제가 없습니다. `RANK_BY`는 O(NR) 키 버퍼에서 대상 키를 찾고 앞선 후보 수를 세며 정렬하지 않습니다. 자동 최적화가 아닌 명시적 선택 연산입니다. [정렬 실측](../bench/ORDERING.md)에서 K/N·selector 비용과 메모리 trade-off를 확인하세요. 특정 속도 향상이나 heap 임계값을 보장하지 않습니다.

## 분할, 중간 누적값과 부수 효과

`PARTITION(predicate)`는 lazy 쿼리도 즉시 한 번 소비하여 독립적인 eager 얕은
스냅샷 `[matching, nonmatching]`을 반환합니다. predicate는 쿼리 순서대로 각
항목에 정확히 한 번 `(value, originalKey)`를 받습니다. 레코드는 객체의 기본
키 순서, 시퀀스는 입력 순서를 유지합니다. 타입 가드는 matching 쪽만 좁힙니다.
가드가 선언한 타입의 일부 값만 인식할 수도 있으므로 nonmatching은 `T`를
유지합니다. 빈 쪽도 타입이 있는 쿼리입니다. 이후 원본의 항목 대입은 스냅샷에
영향을 주지 않지만 참조형 값은 공유합니다.

```ts
import {
  createQueryable, PARTITION, SCAN, TAP, EACH, THROUGH, LAZY, LIMIT, VALUES,
} from "@ilokesto/queryable";

const mixed = createQueryable<string | number>({ a: "one", b: 2 });
const [strings, rest] = mixed[PARTITION](value => typeof value === "string");
// Queryable<string>, Queryable<string | number>

const totals = createQueryable({ a: 1, b: 2, c: 3 })[LAZY]()
  [SCAN]((sum, value, key) => sum + value, () => 0)
  [TAP]((value, key) => { console.info(key, value); });
totals[LIMIT](2)[VALUES](); // [1, 3]; a, b의 effect만 실행
totals[EACH]((value, key) => { console.info(key, value); }); // 전체를 다시 소비
const firstTwo = totals[THROUGH](query => query[LIMIT](2)[VALUES]()); // number[]
```

`SCAN(reducer, seedFactory)`는 원본 키마다 누적값 하나를 내보내며
레코드/시퀀스 모드를 유지합니다. seed 자체는 별도 항목으로 내보내지 않습니다.
reducer의 인자는 `(accumulator, value, originalKey)`입니다. 필수인 인자 없는
factory는 빈 소비를 포함하여 매 소비 시작 시 한 번 호출합니다. 소비하지 않은
lazy 체인이나 후속 `LIMIT(0)`에서는 호출하지 않습니다. lazy 재소비를 독립적으로
유지하려면 factory에서 새로운 mutable seed를 반환하세요.

누적값을 **복제하지 않습니다**. reducer가 같은 객체를 변경하고 반환하면 과거
출력도 그 객체를 참조하여 이후 변경을 관찰합니다. 독립적인 과거 값이 필요하면
각 단계에서 새 객체를 반환하세요. 빈 입력은 아무것도 내보내지 않고 reducer도
호출하지 않습니다.

`TAP(effect)`는 원본 키와 값의 참조 동일성을 유지합니다. `SCAN`과 마찬가지로
eager 쿼리에서는 즉시, lazy 쿼리에서는 수요에 따라 실행합니다. lazy 재소비마다
현재 원본을 다시 읽고 계산하며 memoization하지 않습니다. 후속 `LIMIT`, `FIND`,
`FIRST`, `SOME`은 소비를 일찍 종료할 수 있습니다. `EACH(effect)`는 순서대로
소비하고 `void`를 반환하는 terminal이며 결과 배열을 만들지 않습니다. 두 effect는
`(value, originalKey)`를 받고 `false`를 반환해도 중단하지 않습니다. 빈 입력에서는
effect를 호출하지 않습니다.

`THROUGH(fn)`는 소비 없이 정확히 같은 쿼리 객체로 `fn`을 즉시 한 번 호출하고
반환 타입과 결과의 참조 동일성을 보존합니다. 다섯 메서드 모두 receiver가
필요하고 공유된 동결 prototype을 사용하며 callback이 던진 값을 감싸거나
바꾸지 않고 그대로 전파합니다.

## 값 기준 중복 제거

| 연산 | 결과 |
| --- | --- |
| `[DISTINCT]()` | 전체 입력에서 각 값의 첫 entry 유지 |
| `[DISTINCT_BY]((value, key) => selected)` | 각 selector 결과의 첫 entry 유지 |
| `[DISTINCT_UNTIL_CHANGED]()` | 인접한 동일 값 구간마다 첫 entry 유지 |
| `[DISTINCT_UNTIL_CHANGED_BY]((value, key) => selected)` | 인접한 동일 selector 결과 구간마다 첫 entry 유지 |

```ts
import {
  createQueryable, DISTINCT, DISTINCT_BY, DISTINCT_UNTIL_CHANGED, ENTRIES,
} from "@ilokesto/queryable";

const numbers = createQueryable({ a: 1, b: 1, c: 2, d: 1 });
numbers[DISTINCT]()[ENTRIES](); // [["a", 1], ["c", 2]]
numbers[DISTINCT_UNTIL_CHANGED]()[ENTRIES](); // [["a", 1], ["c", 2], ["d", 1]]
const users = createQueryable({
  alice: { department: "design" },
  bob: { department: "design" },
  charlie: { department: "engineering" },
});
users[DISTINCT_BY](user => user.department)[ENTRIES]();
// alice와 charlie의 원본 값과 키를 유지합니다.
```

동등성은 **SameValueZero**입니다. `NaN`끼리는 같고 `-0`과 `0`도 같습니다.
`undefined`도 일반 값이므로 인접 구간의 첫 값일 때도 보존합니다.
객체와 함수는 내부 필드를 검사하지 않고 참조 identity로 비교합니다.
selector는 방문한 entry마다 원본 값과 키를 한 번 받습니다. 반환값은 동등성
판단에만 사용하며 원본 값이나 키를 대체하지 않습니다. 사용자 comparator는
제공하지 않습니다. 임의 동등성은 Set 조회 대신 이전 대표 값들과 후보를
비교하는 추가 비용이 필요할 수 있습니다.

레코드 **키**가 유일해도 **값**은 중복될 수 있습니다. `PICK`은 요청한 키의
중복을 무시하지만 distinct 연산은 서로 다른 원본 키의 값이나 selector
결과를 비교합니다. 항상 첫 entry가 남습니다. 레코드는 네이티브 객체 순서,
정렬된 시퀀스는 순회 순서를 유지합니다. 원본 표현을 유지하며 입력은 변경하지
않습니다.

레코드와 즉시 평가 시퀀스는 호출 즉시 실행합니다. `LAZY` 이후 네 연산은
소비 시 스트리밍하며 뒤의 조기 종료 연산을 지원합니다. 부분 소비나 예외 이후에도
매 소비마다 상태를 새로 만듭니다. 전체 distinct는 선택된 고유 값 수만큼의
Set 공간을 사용하고, 인접 distinct는 초기화 여부와 직전 선택 값만 보관하므로
상수 공간을 사용합니다. 전체 entry 버퍼링이나 결과 메모이제이션은 하지 않습니다.
지연 뷰는 live·repeatable 계약을 유지하며 selector 예외는 그대로 전파됩니다.
다음 소비는 처음부터 다시 시작합니다.

## 숫자 집계와 그룹별 집계

아래 종단 메서드는 레코드, 즉시 평가 정렬 시퀀스, 지연 시퀀스에서 모두 동작합니다. 호출하면 남은 연산을 소스 순서대로 즉시 소비하며 콜백에는 원래 레코드 키를 전달합니다. 숨겨진 소스 캐시는 없습니다. 지연 쿼리를 다시 소비하면 콜백을 다시 실행하고 쿼리 레코드의 변경을 읽습니다.

| 종단 메서드 | 결과 |
| --- | --- |
| `[SUM]((value, key) => number)` | `+0`부터 누적한 합; 빈 입력은 `0` |
| `[AVERAGE]((value, key) => number)` | 합을 개수로 나눈 평균; 빈 입력은 `undefined` |
| `[MIN]((value, key) => number)` | 최솟값; 빈 입력은 `undefined` |
| `[MAX]((value, key) => number)` | 최댓값; 빈 입력은 `undefined` |
| `[STATS]((value, key) => number)` | `NumericStats`: `{ count, sum, average, min, max }` |
| `[COUNT_BY]((value, key) => K)` | 문자열 그룹별 개수인 `Partial<Record<K, number>>` |
| `[REDUCE_BY](keyFn, initial, reducer)` | 문자열 그룹별 누적값인 `Partial<Record<K, A>>` |

```ts
import {
  createQueryable, SUM, AVERAGE, MIN, MAX, STATS, COUNT_BY, REDUCE_BY,
} from "@ilokesto/queryable";

const sales = createQueryable({
  alice: { team: "red", amount: 10 },
  bob: { team: "blue", amount: 20 },
  carol: { team: "red", amount: 30 },
});
sales[SUM](sale => sale.amount); // 60
sales[AVERAGE](sale => sale.amount); // 20
sales[MIN](sale => sale.amount); // 10
sales[MAX](sale => sale.amount); // 30
sales[STATS](sale => sale.amount);
// { count: 3, sum: 60, average: 20, min: 10, max: 30 }
sales[COUNT_BY](sale => sale.team); // { red: 2, blue: 1 }

const totals = sales[REDUCE_BY](
  sale => sale.team === "red" ? "red" : "blue",
  _groupKey => ({ total: 0, members: [] as string[] }),
  (acc, sale, key) => {
    acc.total += sale.amount;
    acc.members.push(key);
    return acc;
  },
);
// Partial<Record<"red" | "blue", { total: number; members: string[] }>>
totals.red?.total; // 40
```

숫자 selector는 필수이며 반환 타입은 `number`만 받습니다. `bigint` 합계는 bigint 쿼리에서 `query[REDUCE]((total, value) => total + value, 0n)`처럼 직접 누적하세요. `STATS`는 한 번 순회하면서 항목마다 selector를 정확히 한 번 호출하여 다섯 필드를 함께 계산합니다. 소스를 필드마다 다시 소비하지 않습니다. 개별 숫자 종단 메서드도 항목마다 selector를 한 번 호출합니다. 빈 `STATS` 결과는 `{ count: 0, sum: 0, average: undefined, min: undefined, max: undefined }`입니다.

숫자를 거르거나 강제 변환하지 않고 JavaScript 연산을 따릅니다. 합은 `+0`부터 왼쪽 순서대로 `+`로 누적하며 평균은 합을 개수로 나눕니다. 최솟값·최댓값은 `Math.min`·`Math.max` 규칙을 따릅니다. `NaN`은 숫자 결과에 전파되지만 개수에는 포함됩니다. 무한대와 오버플로는 그대로 유지하고, 부호가 반대인 무한대를 더하면 `NaN`이 됩니다. 부동소수점 반올림 결과는 소스 순서에 따릅니다. `-0`만 있는 합과 평균은 `+0`이며, 최솟값·최댓값은 단독 `-0`을 유지합니다. 두 부호의 0이 섞이면 최솟값은 `-0`, 최댓값은 `+0`입니다. `NaN`을 만나도 콜백이 예외를 던지지 않는 한 남은 항목과 selector를 모두 실행합니다.

`REDUCE_BY`는 `keyFn(value, key)`, **초기 누적값 팩토리** `initial(groupKey)`, `reducer(accumulator, value, key)` 순서로 인자를 받습니다. 팩토리를 먼저 받아 reducer의 누적값 타입을 추론합니다. 각 항목에서 그룹 키를 구한 뒤 그 그룹의 첫 항목이면 팩토리를 실행하고 reducer를 호출합니다. 첫 항목도 reducer에 전달합니다. 팩토리는 종단 호출마다 실제 등장한 그룹당 한 번만 실행하며, 없는 그룹이나 빈 입력에서는 실행하지 않습니다. 그룹마다 별도 변경 가능한 상태가 필요하면 팩토리에서 새 객체를 반환하세요. reducer의 반환값이 해당 그룹의 다음 누적값이며 `undefined`, `null`, `false`, `0`, `""`도 보존합니다. 저장된 `undefined`를 초기화되지 않은 그룹으로 취급하지 않습니다.

두 그룹별 종단 메서드는 그룹 전체를 저장하지 않고 직접 누적합니다. 결과 객체의 프로토타입은 null이므로 `""`, `__proto__`, `constructor`, `toString`도 안전한 문자열 그룹 키입니다. 키 리터럴 유니온을 추론하지만 그룹이 없을 수 있으므로 각 속성은 optional입니다. 없는 그룹과 `undefined` 누적값을 가진 그룹은 `Object.hasOwn(result, key)`로 구분하세요. 결과 속성의 열거 순서는 정수형 키를 포함한 네이티브 객체 순서를 따르며, 그룹 내부 reducer는 안정적인 소스 순서대로 호출됩니다. 앞선 연산, selector, 팩토리, reducer의 예외는 즉시 전파됩니다. 지연 쿼리를 다시 소비하면 처음부터 순회하고 누적값도 새로 만듭니다.

`GROUP_BY`는 계속 그룹 전체를 즉시 계산한 스냅샷으로 만들어 후속 쿼리를 지원합니다. 그룹 내용이 필요하면 `GROUP_BY`, 그룹별 개수나 누적값만 필요하면 `COUNT_BY`·`REDUCE_BY`를 사용하세요.

## 조회와 기본값

다음 종단 메서드는 레코드, 정렬 시퀀스, 지연 뷰에서 같은 함수를 공유하며 쿼리 순서를 따릅니다.

| 연산 | 결과 |
| --- | --- |
| `[LAST]()` | 마지막 값. 비어 있으면 `undefined` |
| `[AT](index)` | 0부터 시작하는 위치의 값. 음수는 뒤에서부터 계산 |
| `[SINGLE](predicate?)` | 유일한 일치 값. 일치 항목이 없으면 `undefined`, 두 번째 일치 항목에서 `RangeError` |
| `[EVERY](predicate)` | 모든 값의 조건 만족 여부. 비어 있으면 `true` |
| `[IS_EMPTY]()` | 항목이 없는지 여부 |
| `[INCLUDES](value)` | SameValueZero로 값의 존재 여부 검사 (`NaN`끼리, `0`과 `-0`은 일치하며 객체는 참조 비교) |
| `[FIND_ENTRY](predicate)` | 첫 일치 항목의 새 `[key, value]` 튜플. 없으면 `undefined` |
| `[FIRST_OR](value)` | 첫 값. 비어 있을 때만 전달한 기본값 사용 |
| `[FIRST_OR_ELSE](factory)` | 첫 값. 비어 있을 때만 인자 없는 팩터리를 정확히 한 번 호출 |

조건 함수는 `(value, key)`를 받습니다. 조건 없는 `SINGLE`은 모든 항목을 세며, 조건이 있으면 일치 항목만 셉니다. 저장된 `undefined`도 일치 항목이므로 두 번째 항목이 있으면 예외가 발생합니다. `SINGLE`과 `FIND_ENTRY`는 타입 가드의 좁히기를 보존합니다. 반환 튜플은 새 컨테이너이고 값의 참조는 공유합니다.

`AT`는 `Array.at`의 숫자 변환을 따릅니다. 소수는 0 방향으로 절삭하고 `NaN`과 양수·음수 0은 첫 항목을 선택합니다. 양수·음수 무한대는 순회하거나 지연 콜백을 실행하지 않고 `undefined`를 반환합니다. 숫자 변환 오류는 순회 전에 그대로 전파합니다. 유한한 0 이상 인덱스는 해당 항목에서 멈추며 범위를 벗어나면 끝까지 순회합니다. 유한한 음수 인덱스는 전체를 소비하고 최대 `min(항목 수, abs(절삭한 인덱스))`개의 값을 버퍼링합니다. `LAST`도 전체를 소비합니다. `SINGLE`은 끝 또는 두 번째 일치 항목까지 소비하며 나머지 조회는 결과를 결정하는 즉시 멈춥니다. 지연 뷰를 다시 조회하면 대기 중인 작업도 다시 실행합니다.

항목 존재 여부를 truthiness나 값이 `undefined`인지로 판단하지 않습니다. 기존 `FIRST`와 `FIND`는 부재와 저장된 `undefined`를 모두 `undefined`로 반환하지만 기본값 조회는 항목의 존재를 구분하여 저장된 `0`, `false`, `undefined`를 유지합니다. 조건 함수와 팩터리의 오류는 변경 없이 전파합니다.

```ts
import {
  createQueryable, AT, FIND_ENTRY, FIRST_OR, FIRST_OR_ELSE, SINGLE,
} from "@ilokesto/queryable";

const query = createQueryable<number | string | undefined>({ a: undefined, b: 0, c: "three" });
query[FIRST_OR](99); // undefined: "a" 항목이 존재함
query[FIRST_OR_ELSE](() => 99); // undefined: 팩터리를 호출하지 않음
query[AT](-1); // "three"
query[SINGLE]((value): value is string => typeof value === "string"); // string | undefined
query[FIND_ENTRY]((value): value is string => typeof value === "string"); // [string, string] | undefined
```

## 범위와 접두 구간

다음 공유 Symbol 연산은 원래 키와 쿼리 모드를 유지합니다. 레코드는 레코드, 정렬·지연 시퀀스는 시퀀스를 반환합니다. 즉시 평가 쿼리에서는 호출 즉시 실행하며 지연 쿼리에서는 소비 시점까지 미룹니다.

| 연산 | 결과 |
| --- | --- |
| `[SKIP](n)` | 앞의 `n`개 제외 |
| `[TAKE_WHILE]((value, key) => boolean)` | 처음 불일치하기 전까지 일치하는 접두 구간 유지 |
| `[DROP_WHILE]((value, key) => boolean)` | 일치하는 접두 구간 제외; 첫 불일치 항목은 유지 |
| `[TAKE_LAST](n)` | 마지막 `n`개를 입력 순서대로 유지 |
| `[DROP_LAST](n)` | 마지막 `n`개를 제외하고 입력 순서 유지 |

세 숫자 연산의 크기 정규화는 같습니다. 소수는 0 방향으로 절삭하고, 음수(`-Infinity` 포함)와 `NaN`은 0으로 바꾸며 `Infinity`는 유지합니다. 따라서 `SKIP(0)`과 `DROP_LAST(0)`은 전체를 유지하고, `TAKE_LAST(0)`은 원본을 읽지 않고 빈 결과를 냅니다. 기존 `LIMIT`의 부호 있는 `slice(0, n)` 계약은 바꾸지 않습니다.

```ts
import {
  createQueryable, LAZY, SKIP, LIMIT, TAKE_WHILE, DROP_WHILE,
  TAKE_LAST, DROP_LAST, VALUES,
} from "@ilokesto/queryable";

const query = createQueryable({ a: 1, b: 2, c: 3, d: 2 });
query[LAZY]()[SKIP](1)[LIMIT](2)[VALUES](); // [2, 3]
query[TAKE_WHILE](n => n < 3)[VALUES](); // [1, 2]
query[DROP_WHILE](n => n < 3)[VALUES](); // [3, 2]
query[TAKE_LAST](2)[VALUES](); // [3, 2]
query[DROP_LAST](2)[VALUES](); // [1, 2]
```

비음수 범위는 `SKIP(start)[LIMIT](length)`로 표현하며 별도의 `SLICE` 연산은 제공하지 않습니다. 레코드의 정수형 키에는 객체 열거 규칙이 적용되고 시퀀스는 앞선 순서를 유지합니다. 저장된 `undefined`와 특수 키도 그대로 보존합니다.

`TAKE_WHILE`은 첫 불일치에서 종료하며 타입 가드를 지원합니다. `DROP_WHILE`은 첫 불일치 이후 predicate를 더 호출하지 않습니다. 이후 값 전체를 거르는 연산이 아니므로 값 타입을 좁히지 않습니다. 두 predicate 모두 원래 키를 받습니다.

지연 쿼리의 `SKIP(n)[FIRST]()`는 최대 `n + 1`개를 읽고, `TAKE_WHILE(predicate)[LIMIT](k)`는 필요한 접두 구간까지만 읽어 다음 항목을 검사하지 않습니다. `TAKE_LAST(n)`은 전체 입력을 읽은 뒤 결과를 내며 유한한 크기에는 최대 `n`개를 링 버퍼에 저장합니다. `DROP_LAST(n)`은 최대 `n`개를 저장하고 첫 출력을 위해 `n + 1`개를 읽습니다. 이후 조기 종료하는 터미널은 남은 순회를 멈출 수 있습니다. 정렬, 시퀀스 `PICK`, 음수 `LIMIT`의 버퍼링 장벽을 건너뛰지 않습니다.

`SKIP(Infinity)`와 `DROP_LAST(Infinity)`는 전체를 소비하고 빈 결과를 냅니다. 후자는 항목을 저장하지 않습니다. `TAKE_LAST(Infinity)`는 전체 입력을 소비·저장한 뒤 모두 반환합니다. 소비할 때마다 카운터, predicate 상태, 버퍼를 새로 만듭니다. 조기 종료나 예외 이후에도 같으며, 지연 콜백과 예외는 소비 시점에 실행되고 소비 사이의 변경은 다음 순회에 반영됩니다.

## Iterable 원본과 키 identity

`createQuerySequence(factory, options?)`는
`Iterable<readonly [string, T]>`를 만드는 factory로 지연 시퀀스를 생성합니다.
생성 시점에는 factory를 호출하지 않고, 소비할 때마다 다시 호출합니다.
새 iterator나 반복 가능한 iterable을 반환하세요. 이미 소진한 generator를
재사용하지 않으며 결과 캐시나 자동 되감기도 제공하지 않습니다.

```ts
import { createQuerySequence, iterateEntries, iterateValues } from "@ilokesto/queryable";

const rows = new Map([["2", 20], ["1", 10]]);
const query = createQuerySequence(() => rows.entries());
const entries = iterateEntries(query); // 아직 소비하지 않음
[...entries]; // [["2", 20], ["1", 10]]
rows.set("2", 30);
[...iterateValues(query)]; // [30, 10]
```

`iterateEntries(query)`와 `iterateValues(query)`는 배열을 먼저 만들지 않고
레코드와 시퀀스를 연결합니다. 각 iterator는 독립적입니다. entry 뷰의 새 튜플을
수정해도 버퍼링된 쿼리는 바뀌지 않지만, 값 자체는 얕은 참조입니다.
쿼리 자체의 기본 iterator 대신 entry와 value 중 하나를 명시적으로 고릅니다.

외부 entry는 문자열 키를 가진 길이 2의 배열이어야 합니다. `undefined`, Symbol,
opaque 객체를 포함한 값은 검사하지 않습니다. 잘못된 entry는 읽는 시점에
`TypeError`를 던집니다. 조기 종료와 downstream 예외는 획득한 generator를
닫으며, `LIMIT(0)`은 원본을 획득하지 않습니다.

`duplicateKeys` 옵션으로 키 충돌을 명시합니다.

| 정책 | 동작 |
| --- | --- |
| `"error"` (기본값) | 중복 entry를 읽으면 `DuplicateKeyError`를 던지며 `key`에 충돌한 키가 있음 |
| `"first"` | 저장된 `undefined`도 포함하여 첫 값을 유지하고 이후 중복은 건너뜀 |
| `"last"` | 전체 원본을 소비한 뒤 각 키의 첫 위치를 유지하며 마지막 값을 출력 |

identity 상태는 매 소비마다 새로 만듭니다. streaming 정책은 관찰한 키의 Set을,
`"last"`는 모든 고유 키의 Map을 보관합니다. prefix 소비는 실제 읽은 부분만
검증하므로 뒤쪽까지 고유하다고 보증하지 않습니다. 전체 소비는 기본적으로
중복 키를 조용히 덮어쓰지 않고 거부합니다. PICK·그룹·정렬·컬렉션 출력도
이 고유 키 경계를 사용하며, 이후 다중 원본 연산의 공통 identity 계약이 됩니다.
`TO_OBJECT`는 계속 숫자 키에 네이티브 객체 열거 순서를 적용합니다.
