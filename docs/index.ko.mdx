# Queryable

버전 **0.0.1**, 비공개 베타입니다. npm에 배포하지 않았으며 로컬 문서는 `next` 채널만 제공합니다.

```ts
import { createQueryable, WHERE, SORT, LIMIT, MAP, VALUES } from "@ilokesto/queryable";

const users = createQueryable({
  alice: { name: "Alice", age: 25 },
  bob: { name: "Bob", age: 30 },
  charlie: { name: "Charlie", age: 20 },
});
const names = users[WHERE](user => user.age >= 25)
  [SORT]((a, b) => b.age - a.age)[LIMIT](2)[MAP](user => user.name)[VALUES]();
// ["Bob", "Alice"]
```

## 연산

| 연산 | 결과 |
| --- | --- |
| `[WHERE]((value, key) => boolean)` | 필터 결과; 타입 가드를 받으면 값 타입도 좁힘 |
| `[SORT]((a, b) => number)` | 숫자형 키도 비교 순서를 보장하는 안정 정렬 `QuerySequence` |
| `[MAP]((value, key) => next)` | 키를 유지한 값 변환 |
| `[PICK](...keys)` | 지정한 레코드 키의 값 전체; 없는 키·중복 키는 무시 |
| `[LIMIT](n)` | `slice(0, n)` 의미 |
| `[GROUP_BY]((value, key) => K)` | 즉시 계산한 그룹; 키 리터럴을 보존하는 `Partial<Record<K, ...>>` |
| `[COUNT]()` | 개수 |
| `[FIRST]()` | 첫 값 또는 `undefined` |
| `[VALUES]()` | 순서대로 담은 새 값 배열 |
| `[FIND]((value, key) => boolean)` | 첫 일치 값 또는 `undefined`; 타입 가드 지원 |
| `[SOME]((value, key) => boolean)` | 첫 일치에서 종료하는 boolean 결과 |
| `[ENTRIES]()` | 순서대로 담은 새 `[key, value]` 튜플 배열 |
| `[TO_OBJECT]()` | 쿼리 메서드 없는 일반 객체 |
| `[REDUCE]((acc, value, key) => next, initial)` | 순서대로 누적; 초기값 필수 |
| `[LAZY]()` | 반복 소비 가능한 비메모이제이션 지연 시퀀스 |

## 레코드·시퀀스와 마이그레이션

`createQueryable`은 수정 가능한 `Queryable<T>` 레코드를 반환합니다. 즉시 실행하는 `WHERE`, `MAP`, `PICK`, `LIMIT`은 새 레코드를 만듭니다. `SORT`는 숫자형 키가 다시 정렬되는 문제를 피하도록 `QuerySequence<T>`를 반환하며, 후속 변환도 시퀀스를 유지합니다.

```ts
import { createQueryable, SORT, LIMIT, ENTRIES, TO_OBJECT } from "@ilokesto/queryable";

const sorted = createQueryable({ 1: 10, 2: 20 })[SORT]((a, b) => b - a);
sorted[LIMIT](1)[ENTRIES](); // [["2", 20]]
sorted[TO_OBJECT](); // 일반 객체에서는 숫자 키가 다시 "1", "2" 순서로 열거됨
```

시퀀스 데이터는 `VALUES`·`ENTRIES`·`TO_OBJECT`로 꺼내세요. 직접 키 조회, spread, JSON 직렬화를 데이터 추출 용도로 쓰지 않습니다.

이번 비공개 베타에서 **`SELECT`를 제거하고 `PICK`으로 이름을 변경**했습니다. import와 호출 이름을 바꾸세요. `PICK("alice")`는 값 내부 필드가 아닌 레코드 키를 고릅니다. 필드 추출은 `MAP(user => ({ name: user.name }))`으로 표현합니다. 레코드 PICK의 삽입 순서는 인자 순서지만 숫자 키에는 객체 열거 규칙이 적용됩니다. 시퀀스 PICK은 인자 순서를 그대로 보존합니다.

## 지연 평가 계약

```ts
import { createQueryable, LAZY, WHERE, MAP, LIMIT, VALUES } from "@ilokesto/queryable";

const query = createQueryable({ a: 1, b: 2, c: 3, d: 4 });
const firstEven = query[LAZY]()[WHERE](n => n % 2 === 0)
  [MAP](n => n * 10)[LIMIT](1);
firstEven[VALUES](); // [20]; predicate에는 a와 b만 전달됨
```

- 기본 연산은 호출 즉시 실행합니다. `LAZY` 이후 `WHERE`, `MAP`, `PICK`, `LIMIT`, `SORT`는 소비 시점까지 미룹니다.
- `VALUES`, `ENTRIES`, `TO_OBJECT`, `COUNT`, `REDUCE`, `FIRST`, `FIND`, `SOME`, `GROUP_BY`는 남은 연산을 실행합니다. `FIRST`, `FIND`, `SOME`, 비음수 `LIMIT`은 앞선 순회를 조기 종료합니다. `LIMIT(0)`은 원본도 읽지 않습니다.
- `SORT`, 시퀀스 `PICK`, 유한한 음수 `LIMIT`은 전체 입력이 필요하므로 소비할 때 버퍼링합니다. `GROUP_BY`는 호출 즉시 전체를 읽어 즉시 평가 그룹을 만듭니다. 레코드의 그룹은 레코드, 시퀀스의 그룹은 시퀀스입니다.
- 매번 소비할 때 새로 순회하고 미뤄 둔 콜백을 다시 실행합니다. 캐시는 없습니다. 예외는 소비 시점에 전파되며, 다음 소비는 처음부터 다시 시도합니다.
- 레코드의 지연 뷰는 소비 시점의 **쿼리 레코드**를 읽습니다. 소비 사이에 쿼리를 수정하면 반영됩니다. 생성 전 원본 객체는 이미 얕게 복사했으므로 원본의 속성 교체는 반영되지 않습니다. 정렬된 즉시 평가 시퀀스는 스냅샷이며, 나중에 `LAZY`를 붙여도 이미 실행한 정렬은 다시 실행하지 않습니다.
- 중첩 값은 참조를 공유합니다. 콜백에서 순회 중인 소스 레코드의 키를 추가·삭제하거나 값을 교체하지 마세요. 순회 중 변경에 대한 스냅샷 격리는 제공하지 않습니다.

단일 탐색에는 `FIND`·`SOME`을 쓰세요. 기본 모드의 `WHERE(predicate)[FIRST]()`는 여전히 필터 결과 전체를 먼저 만듭니다.

## 타입과 집계

```ts
import { createQueryable, WHERE, GROUP_BY, REDUCE } from "@ilokesto/queryable";

const mixed = createQueryable<number | string>({ a: 1, b: "two" });
const strings = mixed[WHERE]((value): value is string => typeof value === "string");
// Queryable<string>
const groups = createQueryable({ a: 1, b: 2, c: 3 })
  [GROUP_BY](n => n % 2 ? "odd" : "even");
const oddTotal = groups.odd?.[REDUCE]((sum, n) => sum + n, 0); // 4
```

가능한 그룹 키라도 실제 데이터에는 없을 수 있으므로 optional로 표현합니다. 빈 쿼리의 `REDUCE`는 초기값을 그대로 반환합니다.

## 공통 계약

- 자기 소유의 열거 가능한 문자열 키만 복사합니다. 상속·비열거·Symbol 키는 제외합니다. `__proto__`, `constructor`, `toString`도 일반 데이터 키입니다.
- 생성과 변환은 얕은 복사이며 입력을 변경하지 않습니다.
- `LIMIT`은 소수 절삭, 음수로 뒤쪽 제외, `NaN`은 빈 결과, `Infinity`는 전체라는 `slice` 의미를 유지합니다.
- 메서드는 receiver가 필요합니다. 구조 분해로 떼어 호출하지 마세요. 레코드의 spread·JSON은 데이터만 남기고 메서드는 잃습니다.
- 메서드를 공유하고 동결하지만 특정 메모리 절감률·속도 우위를 보장하지 않습니다.

## Predicate narrowing과 속성별 그룹

`WHERE(Boolean)`과 `FIND(Boolean)`은 값 타입에서 리터럴 `false`, `0`, `0n`, `""`, `null`, `undefined`를 제거합니다. 넓은 `number`, `bigint`, `string`은 그대로 유지합니다. TypeScript는 0·NaN이 아닌 모든 수나 비어 있지 않은 문자열을 완전히 표현하지 못합니다. 리터럴 `false`를 반환하는 콜백의 `WHERE` 결과는 빈 `Queryable<never>` 또는 `QuerySequence<never>`이며, `FIND`는 `undefined`를 반환합니다. 명시적·추론된 타입 가드의 narrowing과 일반 boolean 콜백의 원래 값 타입은 유지합니다. 즉시 평가 레코드·정렬 시퀀스·지연 시퀀스 모두 같은 타입 계약을 사용하며 실행 순서는 바뀌지 않습니다.

```ts
import { createQueryable, WHERE, FIND, VALUES, isDefined, isNonNullish, negate } from "@ilokesto/queryable";

const mixed = createQueryable<0 | false | "" | "cat" | null | undefined>({
  zero: 0, no: false, empty: "", cat: "cat", nil: null, missing: undefined,
});
mixed[WHERE](Boolean)[VALUES](); // ["cat"]; Queryable<"cat">
mixed[WHERE](isDefined)[VALUES](); // [0, false, "", "cat", null]
mixed[WHERE](isNonNullish)[VALUES](); // [0, false, "", "cat"]
mixed[WHERE](negate(isNonNullish))[VALUES](); // [null, undefined]
mixed[FIND](() => false); // undefined
```

`isDefined`는 `undefined`만, `isNonNullish`는 `null`과 `undefined`를 제외합니다. `negate(predicate)`는 모든 콜백 인자를 그대로 전달하고 결과를 반전합니다. 제공된 브랜드가 있는 `isDefined`·`isNonNullish`만 여집합 narrowing을 지원합니다. 임의 타입 가드를 부정하면 boolean predicate를 반환합니다. 양수만 고르는 number 가드는 음수도 거절하므로 부정 결과에서 모든 number를 제외하면 안전하지 않습니다. 헬퍼를 일반 콜백으로 감싸면 브랜드 기반 여집합 계약은 유지되지 않습니다.

`GROUP_BY_PROP(property)`는 문자열 판별 속성의 그룹 키와 해당 값을 가질 수 있는 union member를 연결합니다. 콜백 기반 `GROUP_BY`와 달리 그룹마다 값 타입을 좁히며, 필수 판별 속성이나 빈 입력도 그룹 존재는 optional입니다.

```ts
import { createQueryable, GROUP_BY_PROP, VALUES } from "@ilokesto/queryable";

type Pet = { readonly kind: "cat"; meow: true } | { readonly kind: "dog"; bark: true };
const pets = createQueryable<Pet>({ alice: { kind: "cat", meow: true } });
const groups = pets[GROUP_BY_PROP]("kind");
groups.cat?.[VALUES](); // cat member만 포함, 원래 키 "alice" 유지
groups.dog; // 여기서는 undefined; Queryable<dog member> | undefined
```

선택적 문자열 판별 속성과 속성 자체가 없는 union member도 지원합니다. 속성이 없거나 값이 `undefined`이면 그룹 이름으로 변환하지 않고 건너뜁니다. 그룹 값 타입은 원래의 optional·readonly 속성을 보수적으로 유지하며, 선택적 속성을 필수로 바꾸지 않습니다. 숫자 또는 문자열·숫자 혼합 판별 속성은 받지 않으며 암묵적 숫자 키 변환은 보장하지 않습니다. 런타임에서도 문자열 속성 값만 그룹을 만듭니다.

`GROUP_BY`처럼 `GROUP_BY_PROP`는 미뤄 둔 지연 작업까지 호출 즉시 소비해 얕은 즉시 평가 스냅샷을 만듭니다. 순회 순서대로 각 멤버의 판별 속성을 한 번 읽고 원래 멤버 키와 레코드·시퀀스 모드를 유지합니다. 빈 문자열과 특수 문자열 키를 지원하며 그룹을 다시 소비해도 그룹화 작업을 반복하지 않습니다. 속성 getter 예외는 그대로 전파하고 중첩 값은 참조를 공유합니다.

## selector 정렬과 명시적 선택

```ts
import {
  createQueryable, SORT_BY, MIN_BY, MAX_BY, TOP_K, NTH_BY, RANK_BY, ENTRIES,
} from "@ilokesto/queryable";

const scores = createQueryable({
  alice: { team: "a", score: 8 },
  bob: { team: "a", score: 9 },
  charlie: { team: "b", score: 9 },
});
scores[SORT_BY](
  { select: user => user.team },
  { select: user => user.score, direction: "desc" },
)[ENTRIES](); // bob, alice, charlie
scores[MIN_BY]({ select: user => user.score }); // alice 값
scores[MAX_BY]({ select: user => user.score }); // bob 값: 첫 동점 유지
scores[TOP_K](2, { select: user => user.score, direction: "desc" })[ENTRIES]();
// [["bob", ...], ["charlie", ...]]
scores[NTH_BY](-1, { select: user => user.score }); // charlie 값
scores[RANK_BY]("charlie", { select: user => user.score }); // 2
```

모든 연산은 `select(value, key)`와 선택적 `direction: "asc" | "desc"`(기본 `"asc"`)를 가진 `OrderRule<T>`를 하나 이상 받습니다. 여러 규칙을 사전식으로 비교합니다. `OrderKey`는 `boolean | number | bigint | string | null | undefined`입니다. 오름차순 범주 순서는 **boolean, number, bigint, string, null, undefined**이며 범주 사이에 형 변환하지 않습니다. 범주 안에서는 `false < true`, number·bigint는 숫자 순서, string은 JavaScript UTF-16 사전식 순서(로케일 정렬 아님)입니다. `NaN`은 `Infinity`를 포함한 나머지 number 뒤에 오며 모든 NaN은 동점입니다. `-0`과 `0`도 동점입니다. 내림차순은 nullish 위치를 포함해 키 순서 전체를 뒤집지만, 모든 규칙이 동점이면 어느 방향이든 입력 순서를 유지합니다.

`SORT_BY`와 `TOP_K`는 원래 키를 유지하는 `QuerySequence<T>`를 반환합니다. 숫자 키와 특수 키도 보존합니다. `SORT_BY`는 앞선 규칙이 순서를 결정해도 entry마다 모든 selector를 한 번씩 계산합니다. 키 캐시는 한 번의 소비 동안만 존재하며 지연 소비 간에는 공유하지 않습니다. 즉시 평가 호출은 바로 실행하고 지연 체인은 소비까지 미룬 뒤 현재 쿼리 레코드를 다시 읽고 selector를 다시 실행합니다. 즉시 평가 결과는 entry의 얕은 스냅샷입니다. 원본 레코드나 원본 entry 배열을 제자리 정렬하지 않으며 중첩 값 참조는 공유합니다. 예외는 기존 `SORT`와 같은 즉시/지연 경계에서 원래 객체 그대로 전파합니다. 기존 comparator `SORT`, 반복 `SORT`, `SORT` + `LIMIT`/`FIRST`를 자동 치환하지 않습니다.

`MIN_BY`와 `MAX_BY`는 지연 체인에서도 호출 즉시 소비하는 terminal입니다. 단일 순회에서 최선 entry와 규칙 키만 유지하고 엄격히 개선될 때만 교체하므로 두 극값 모두 첫 동점 값을 반환합니다. 반환값은 entry가 아닌 **값**입니다. 빈 입력은 `undefined`이며 실제로 선택된 undefined 값과 구분되지 않습니다. 키의 존재·위치는 `RANK_BY`, 키와 값은 `TOP_K(...)[ENTRIES]()`로 확인하세요. 방향은 극값에도 적용되므로 내림차순 규칙의 최솟값은 자연 키가 가장 큰 값입니다.

`TOP_K(k, ...rules)`는 최대 K개 후보를 bounded heap으로 유지한 뒤 승자들을 안정 정렬합니다. K가 N 이상이어도 정렬 순서를 보장합니다. K는 비음수 safe integer여야 합니다. `NaN`, 무한대, 소수, 음수, unsafe integer는 지연 소스를 소비하기 전 연산 호출 시 `RangeError`를 던집니다. `-0`은 0이며 K=0은 upstream과 selector를 읽지 않습니다. 양수 K는 뒤에 `FIRST`나 `LIMIT`이 있어도 첫 결과를 내기 전에 전체 upstream을 소비합니다.

`NTH_BY(index, ...rules)`는 같은 정렬의 **0부터 시작하는 안정 ordinal 위치**에 있는 값을 반환합니다. 음수는 뒤에서 셉니다(`-1`은 마지막). 빈 입력·범위 밖은 `undefined`입니다. index는 safe integer여야 하며 잘못된 index는 소비 전에 `RangeError`를 던집니다. `RANK_BY(recordKey, ...rules)`는 해당 키의 0부터 시작하는 안정 ordinal을 반환하고 키가 없으면 `undefined`입니다. 동점도 입력 순서대로 연속된 서로 다른 순위를 받으며 competition/dense rank가 아닙니다. 둘 다 즉시 소비 terminal이며 호출마다 entry당 각 selector를 한 번만 계산합니다.

N개 entry와 R개 규칙에서 `SORT_BY`는 정렬과 O(NR) 키 버퍼를 사용하고 극값은 O(R) 작업 공간을 사용합니다. `TOP_K`는 O(min(K,N)R) 키를 보관하며 비교 비용은 O(N log(min(K,N)) + min(K,N) log(min(K,N)))입니다. `NTH_BY`는 비음수 index에 최대 `index + 1`개, 음수에 최대 `abs(index)`개의 후보를 유지하는 반복형 heap을 사용하여 재귀 분할 문제가 없습니다. `RANK_BY`는 O(NR) 키 버퍼에서 대상 키를 찾고 앞선 후보 수를 세며 정렬하지 않습니다. 자동 최적화가 아닌 명시적 선택 연산입니다. [정렬 실측](../bench/ORDERING.md)에서 K/N·selector 비용과 메모리 trade-off를 확인하세요. 특정 속도 향상이나 heap 임계값을 보장하지 않습니다.

## 분할, 중간 누적값과 부수 효과

`PARTITION(predicate)`는 lazy 쿼리도 즉시 한 번 소비하여 독립적인 eager 얕은
스냅샷 `[matching, nonmatching]`을 반환합니다. predicate는 쿼리 순서대로 각
항목에 정확히 한 번 `(value, originalKey)`를 받습니다. 레코드는 객체의 기본
키 순서, 시퀀스는 입력 순서를 유지합니다. 타입 가드는 matching 쪽만 좁힙니다.
가드가 선언한 타입의 일부 값만 인식할 수도 있으므로 nonmatching은 `T`를
유지합니다. 빈 쪽도 타입이 있는 쿼리입니다. 이후 원본의 항목 대입은 스냅샷에
영향을 주지 않지만 참조형 값은 공유합니다.

```ts
import {
  createQueryable, PARTITION, SCAN, TAP, EACH, THROUGH, LAZY, LIMIT, VALUES,
} from "@ilokesto/queryable";

const mixed = createQueryable<string | number>({ a: "one", b: 2 });
const [strings, rest] = mixed[PARTITION](value => typeof value === "string");
// Queryable<string>, Queryable<string | number>

const totals = createQueryable({ a: 1, b: 2, c: 3 })[LAZY]()
  [SCAN]((sum, value, key) => sum + value, () => 0)
  [TAP]((value, key) => { console.info(key, value); });
totals[LIMIT](2)[VALUES](); // [1, 3]; a, b의 effect만 실행
totals[EACH]((value, key) => { console.info(key, value); }); // 전체를 다시 소비
const firstTwo = totals[THROUGH](query => query[LIMIT](2)[VALUES]()); // number[]
```

`SCAN(reducer, seedFactory)`는 원본 키마다 누적값 하나를 내보내며
레코드/시퀀스 모드를 유지합니다. seed 자체는 별도 항목으로 내보내지 않습니다.
reducer의 인자는 `(accumulator, value, originalKey)`입니다. 필수인 인자 없는
factory는 빈 소비를 포함하여 매 소비 시작 시 한 번 호출합니다. 소비하지 않은
lazy 체인이나 후속 `LIMIT(0)`에서는 호출하지 않습니다. lazy 재소비를 독립적으로
유지하려면 factory에서 새로운 mutable seed를 반환하세요.

누적값을 **복제하지 않습니다**. reducer가 같은 객체를 변경하고 반환하면 과거
출력도 그 객체를 참조하여 이후 변경을 관찰합니다. 독립적인 과거 값이 필요하면
각 단계에서 새 객체를 반환하세요. 빈 입력은 아무것도 내보내지 않고 reducer도
호출하지 않습니다.

`TAP(effect)`는 원본 키와 값의 참조 동일성을 유지합니다. `SCAN`과 마찬가지로
eager 쿼리에서는 즉시, lazy 쿼리에서는 수요에 따라 실행합니다. lazy 재소비마다
현재 원본을 다시 읽고 계산하며 memoization하지 않습니다. 후속 `LIMIT`, `FIND`,
`FIRST`, `SOME`은 소비를 일찍 종료할 수 있습니다. `EACH(effect)`는 순서대로
소비하고 `void`를 반환하는 terminal이며 결과 배열을 만들지 않습니다. 두 effect는
`(value, originalKey)`를 받고 `false`를 반환해도 중단하지 않습니다. 빈 입력에서는
effect를 호출하지 않습니다.

`THROUGH(fn)`는 소비 없이 정확히 같은 쿼리 객체로 `fn`을 즉시 한 번 호출하고
반환 타입과 결과의 참조 동일성을 보존합니다. 다섯 메서드 모두 receiver가
필요하고 공유된 동결 prototype을 사용하며 callback이 던진 값을 감싸거나
바꾸지 않고 그대로 전파합니다.

## 값 기준 중복 제거

| 연산 | 결과 |
| --- | --- |
| `[DISTINCT]()` | 전체 입력에서 각 값의 첫 entry 유지 |
| `[DISTINCT_BY]((value, key) => selected)` | 각 selector 결과의 첫 entry 유지 |
| `[DISTINCT_UNTIL_CHANGED]()` | 인접한 동일 값 구간마다 첫 entry 유지 |
| `[DISTINCT_UNTIL_CHANGED_BY]((value, key) => selected)` | 인접한 동일 selector 결과 구간마다 첫 entry 유지 |

```ts
import {
  createQueryable, DISTINCT, DISTINCT_BY, DISTINCT_UNTIL_CHANGED, ENTRIES,
} from "@ilokesto/queryable";

const numbers = createQueryable({ a: 1, b: 1, c: 2, d: 1 });
numbers[DISTINCT]()[ENTRIES](); // [["a", 1], ["c", 2]]
numbers[DISTINCT_UNTIL_CHANGED]()[ENTRIES](); // [["a", 1], ["c", 2], ["d", 1]]
const users = createQueryable({
  alice: { department: "design" },
  bob: { department: "design" },
  charlie: { department: "engineering" },
});
users[DISTINCT_BY](user => user.department)[ENTRIES]();
// alice와 charlie의 원본 값과 키를 유지합니다.
```

동등성은 **SameValueZero**입니다. `NaN`끼리는 같고 `-0`과 `0`도 같습니다.
`undefined`도 일반 값이므로 인접 구간의 첫 값일 때도 보존합니다.
객체와 함수는 내부 필드를 검사하지 않고 참조 identity로 비교합니다.
selector는 방문한 entry마다 원본 값과 키를 한 번 받습니다. 반환값은 동등성
판단에만 사용하며 원본 값이나 키를 대체하지 않습니다. 사용자 comparator는
제공하지 않습니다. 임의 동등성은 Set 조회 대신 이전 대표 값들과 후보를
비교하는 추가 비용이 필요할 수 있습니다.

레코드 **키**가 유일해도 **값**은 중복될 수 있습니다. `PICK`은 요청한 키의
중복을 무시하지만 distinct 연산은 서로 다른 원본 키의 값이나 selector
결과를 비교합니다. 항상 첫 entry가 남습니다. 레코드는 네이티브 객체 순서,
정렬된 시퀀스는 순회 순서를 유지합니다. 원본 표현을 유지하며 입력은 변경하지
않습니다.

레코드와 즉시 평가 시퀀스는 호출 즉시 실행합니다. `LAZY` 이후 네 연산은
소비 시 스트리밍하며 뒤의 조기 종료 연산을 지원합니다. 부분 소비나 예외 이후에도
매 소비마다 상태를 새로 만듭니다. 전체 distinct는 선택된 고유 값 수만큼의
Set 공간을 사용하고, 인접 distinct는 초기화 여부와 직전 선택 값만 보관하므로
상수 공간을 사용합니다. 전체 entry 버퍼링이나 결과 메모이제이션은 하지 않습니다.
지연 뷰는 live·repeatable 계약을 유지하며 selector 예외는 그대로 전파됩니다.
다음 소비는 처음부터 다시 시작합니다.

## 숫자 집계와 그룹별 집계

아래 종단 메서드는 레코드, 즉시 평가 정렬 시퀀스, 지연 시퀀스에서 모두 동작합니다. 호출하면 남은 연산을 소스 순서대로 즉시 소비하며 콜백에는 원래 레코드 키를 전달합니다. 숨겨진 소스 캐시는 없습니다. 지연 쿼리를 다시 소비하면 콜백을 다시 실행하고 쿼리 레코드의 변경을 읽습니다.

| 종단 메서드 | 결과 |
| --- | --- |
| `[SUM]((value, key) => number)` | `+0`부터 누적한 합; 빈 입력은 `0` |
| `[AVERAGE]((value, key) => number)` | 합을 개수로 나눈 평균; 빈 입력은 `undefined` |
| `[MIN]((value, key) => number)` | 최솟값; 빈 입력은 `undefined` |
| `[MAX]((value, key) => number)` | 최댓값; 빈 입력은 `undefined` |
| `[STATS]((value, key) => number)` | `NumericStats`: `{ count, sum, average, min, max }` |
| `[COUNT_BY]((value, key) => K)` | 문자열 그룹별 개수인 `Partial<Record<K, number>>` |
| `[REDUCE_BY](keyFn, initial, reducer)` | 문자열 그룹별 누적값인 `Partial<Record<K, A>>` |

```ts
import {
  createQueryable, SUM, AVERAGE, MIN, MAX, STATS, COUNT_BY, REDUCE_BY,
} from "@ilokesto/queryable";

const sales = createQueryable({
  alice: { team: "red", amount: 10 },
  bob: { team: "blue", amount: 20 },
  carol: { team: "red", amount: 30 },
});
sales[SUM](sale => sale.amount); // 60
sales[AVERAGE](sale => sale.amount); // 20
sales[MIN](sale => sale.amount); // 10
sales[MAX](sale => sale.amount); // 30
sales[STATS](sale => sale.amount);
// { count: 3, sum: 60, average: 20, min: 10, max: 30 }
sales[COUNT_BY](sale => sale.team); // { red: 2, blue: 1 }

const totals = sales[REDUCE_BY](
  sale => sale.team === "red" ? "red" : "blue",
  _groupKey => ({ total: 0, members: [] as string[] }),
  (acc, sale, key) => {
    acc.total += sale.amount;
    acc.members.push(key);
    return acc;
  },
);
// Partial<Record<"red" | "blue", { total: number; members: string[] }>>
totals.red?.total; // 40
```

숫자 selector는 필수이며 반환 타입은 `number`만 받습니다. `bigint` 합계는 bigint 쿼리에서 `query[REDUCE]((total, value) => total + value, 0n)`처럼 직접 누적하세요. `STATS`는 한 번 순회하면서 항목마다 selector를 정확히 한 번 호출하여 다섯 필드를 함께 계산합니다. 소스를 필드마다 다시 소비하지 않습니다. 개별 숫자 종단 메서드도 항목마다 selector를 한 번 호출합니다. 빈 `STATS` 결과는 `{ count: 0, sum: 0, average: undefined, min: undefined, max: undefined }`입니다.

숫자를 거르거나 강제 변환하지 않고 JavaScript 연산을 따릅니다. 합은 `+0`부터 왼쪽 순서대로 `+`로 누적하며 평균은 합을 개수로 나눕니다. 최솟값·최댓값은 `Math.min`·`Math.max` 규칙을 따릅니다. `NaN`은 숫자 결과에 전파되지만 개수에는 포함됩니다. 무한대와 오버플로는 그대로 유지하고, 부호가 반대인 무한대를 더하면 `NaN`이 됩니다. 부동소수점 반올림 결과는 소스 순서에 따릅니다. `-0`만 있는 합과 평균은 `+0`이며, 최솟값·최댓값은 단독 `-0`을 유지합니다. 두 부호의 0이 섞이면 최솟값은 `-0`, 최댓값은 `+0`입니다. `NaN`을 만나도 콜백이 예외를 던지지 않는 한 남은 항목과 selector를 모두 실행합니다.

`REDUCE_BY`는 `keyFn(value, key)`, **초기 누적값 팩토리** `initial(groupKey)`, `reducer(accumulator, value, key)` 순서로 인자를 받습니다. 팩토리를 먼저 받아 reducer의 누적값 타입을 추론합니다. 각 항목에서 그룹 키를 구한 뒤 그 그룹의 첫 항목이면 팩토리를 실행하고 reducer를 호출합니다. 첫 항목도 reducer에 전달합니다. 팩토리는 종단 호출마다 실제 등장한 그룹당 한 번만 실행하며, 없는 그룹이나 빈 입력에서는 실행하지 않습니다. 그룹마다 별도 변경 가능한 상태가 필요하면 팩토리에서 새 객체를 반환하세요. reducer의 반환값이 해당 그룹의 다음 누적값이며 `undefined`, `null`, `false`, `0`, `""`도 보존합니다. 저장된 `undefined`를 초기화되지 않은 그룹으로 취급하지 않습니다.

두 그룹별 종단 메서드는 그룹 전체를 저장하지 않고 직접 누적합니다. 결과 객체의 프로토타입은 null이므로 `""`, `__proto__`, `constructor`, `toString`도 안전한 문자열 그룹 키입니다. 키 리터럴 유니온을 추론하지만 그룹이 없을 수 있으므로 각 속성은 optional입니다. 없는 그룹과 `undefined` 누적값을 가진 그룹은 `Object.hasOwn(result, key)`로 구분하세요. 결과 속성의 열거 순서는 정수형 키를 포함한 네이티브 객체 순서를 따르며, 그룹 내부 reducer는 안정적인 소스 순서대로 호출됩니다. 앞선 연산, selector, 팩토리, reducer의 예외는 즉시 전파됩니다. 지연 쿼리를 다시 소비하면 처음부터 순회하고 누적값도 새로 만듭니다.

`GROUP_BY`는 계속 그룹 전체를 즉시 계산한 스냅샷으로 만들어 후속 쿼리를 지원합니다. 그룹 내용이 필요하면 `GROUP_BY`, 그룹별 개수나 누적값만 필요하면 `COUNT_BY`·`REDUCE_BY`를 사용하세요.

## 조회와 기본값

다음 종단 메서드는 레코드, 정렬 시퀀스, 지연 뷰에서 같은 함수를 공유하며 쿼리 순서를 따릅니다.

| 연산 | 결과 |
| --- | --- |
| `[LAST]()` | 마지막 값. 비어 있으면 `undefined` |
| `[AT](index)` | 0부터 시작하는 위치의 값. 음수는 뒤에서부터 계산 |
| `[SINGLE](predicate?)` | 유일한 일치 값. 일치 항목이 없으면 `undefined`, 두 번째 일치 항목에서 `RangeError` |
| `[EVERY](predicate)` | 모든 값의 조건 만족 여부. 비어 있으면 `true` |
| `[IS_EMPTY]()` | 항목이 없는지 여부 |
| `[INCLUDES](value)` | SameValueZero로 값의 존재 여부 검사 (`NaN`끼리, `0`과 `-0`은 일치하며 객체는 참조 비교) |
| `[FIND_ENTRY](predicate)` | 첫 일치 항목의 새 `[key, value]` 튜플. 없으면 `undefined` |
| `[FIRST_OR](value)` | 첫 값. 비어 있을 때만 전달한 기본값 사용 |
| `[FIRST_OR_ELSE](factory)` | 첫 값. 비어 있을 때만 인자 없는 팩터리를 정확히 한 번 호출 |

조건 함수는 `(value, key)`를 받습니다. 조건 없는 `SINGLE`은 모든 항목을 세며, 조건이 있으면 일치 항목만 셉니다. 저장된 `undefined`도 일치 항목이므로 두 번째 항목이 있으면 예외가 발생합니다. `SINGLE`과 `FIND_ENTRY`는 타입 가드의 좁히기를 보존합니다. 반환 튜플은 새 컨테이너이고 값의 참조는 공유합니다.

`AT`는 `Array.at`의 숫자 변환을 따릅니다. 소수는 0 방향으로 절삭하고 `NaN`과 양수·음수 0은 첫 항목을 선택합니다. 양수·음수 무한대는 순회하거나 지연 콜백을 실행하지 않고 `undefined`를 반환합니다. 숫자 변환 오류는 순회 전에 그대로 전파합니다. 유한한 0 이상 인덱스는 해당 항목에서 멈추며 범위를 벗어나면 끝까지 순회합니다. 유한한 음수 인덱스는 전체를 소비하고 최대 `min(항목 수, abs(절삭한 인덱스))`개의 값을 버퍼링합니다. `LAST`도 전체를 소비합니다. `SINGLE`은 끝 또는 두 번째 일치 항목까지 소비하며 나머지 조회는 결과를 결정하는 즉시 멈춥니다. 지연 뷰를 다시 조회하면 대기 중인 작업도 다시 실행합니다.

항목 존재 여부를 truthiness나 값이 `undefined`인지로 판단하지 않습니다. 기존 `FIRST`와 `FIND`는 부재와 저장된 `undefined`를 모두 `undefined`로 반환하지만 기본값 조회는 항목의 존재를 구분하여 저장된 `0`, `false`, `undefined`를 유지합니다. 조건 함수와 팩터리의 오류는 변경 없이 전파합니다.

```ts
import {
  createQueryable, AT, FIND_ENTRY, FIRST_OR, FIRST_OR_ELSE, SINGLE,
} from "@ilokesto/queryable";

const query = createQueryable<number | string | undefined>({ a: undefined, b: 0, c: "three" });
query[FIRST_OR](99); // undefined: "a" 항목이 존재함
query[FIRST_OR_ELSE](() => 99); // undefined: 팩터리를 호출하지 않음
query[AT](-1); // "three"
query[SINGLE]((value): value is string => typeof value === "string"); // string | undefined
query[FIND_ENTRY]((value): value is string => typeof value === "string"); // [string, string] | undefined
```

## 범위와 접두 구간

다음 공유 Symbol 연산은 원래 키와 쿼리 모드를 유지합니다. 레코드는 레코드, 정렬·지연 시퀀스는 시퀀스를 반환합니다. 즉시 평가 쿼리에서는 호출 즉시 실행하며 지연 쿼리에서는 소비 시점까지 미룹니다.

| 연산 | 결과 |
| --- | --- |
| `[SKIP](n)` | 앞의 `n`개 제외 |
| `[TAKE_WHILE]((value, key) => boolean)` | 처음 불일치하기 전까지 일치하는 접두 구간 유지 |
| `[DROP_WHILE]((value, key) => boolean)` | 일치하는 접두 구간 제외; 첫 불일치 항목은 유지 |
| `[TAKE_LAST](n)` | 마지막 `n`개를 입력 순서대로 유지 |
| `[DROP_LAST](n)` | 마지막 `n`개를 제외하고 입력 순서 유지 |

세 숫자 연산의 크기 정규화는 같습니다. 소수는 0 방향으로 절삭하고, 음수(`-Infinity` 포함)와 `NaN`은 0으로 바꾸며 `Infinity`는 유지합니다. 따라서 `SKIP(0)`과 `DROP_LAST(0)`은 전체를 유지하고, `TAKE_LAST(0)`은 원본을 읽지 않고 빈 결과를 냅니다. 기존 `LIMIT`의 부호 있는 `slice(0, n)` 계약은 바꾸지 않습니다.

```ts
import {
  createQueryable, LAZY, SKIP, LIMIT, TAKE_WHILE, DROP_WHILE,
  TAKE_LAST, DROP_LAST, VALUES,
} from "@ilokesto/queryable";

const query = createQueryable({ a: 1, b: 2, c: 3, d: 2 });
query[LAZY]()[SKIP](1)[LIMIT](2)[VALUES](); // [2, 3]
query[TAKE_WHILE](n => n < 3)[VALUES](); // [1, 2]
query[DROP_WHILE](n => n < 3)[VALUES](); // [3, 2]
query[TAKE_LAST](2)[VALUES](); // [3, 2]
query[DROP_LAST](2)[VALUES](); // [1, 2]
```

비음수 범위는 `SKIP(start)[LIMIT](length)`로 표현하며 별도의 `SLICE` 연산은 제공하지 않습니다. 레코드의 정수형 키에는 객체 열거 규칙이 적용되고 시퀀스는 앞선 순서를 유지합니다. 저장된 `undefined`와 특수 키도 그대로 보존합니다.

`TAKE_WHILE`은 첫 불일치에서 종료하며 타입 가드를 지원합니다. `DROP_WHILE`은 첫 불일치 이후 predicate를 더 호출하지 않습니다. 이후 값 전체를 거르는 연산이 아니므로 값 타입을 좁히지 않습니다. 두 predicate 모두 원래 키를 받습니다.

지연 쿼리의 `SKIP(n)[FIRST]()`는 최대 `n + 1`개를 읽고, `TAKE_WHILE(predicate)[LIMIT](k)`는 필요한 접두 구간까지만 읽어 다음 항목을 검사하지 않습니다. `TAKE_LAST(n)`은 전체 입력을 읽은 뒤 결과를 내며 유한한 크기에는 최대 `n`개를 링 버퍼에 저장합니다. `DROP_LAST(n)`은 최대 `n`개를 저장하고 첫 출력을 위해 `n + 1`개를 읽습니다. 이후 조기 종료하는 터미널은 남은 순회를 멈출 수 있습니다. 정렬, 시퀀스 `PICK`, 음수 `LIMIT`의 버퍼링 장벽을 건너뛰지 않습니다.

`SKIP(Infinity)`와 `DROP_LAST(Infinity)`는 전체를 소비하고 빈 결과를 냅니다. 후자는 항목을 저장하지 않습니다. `TAKE_LAST(Infinity)`는 전체 입력을 소비·저장한 뒤 모두 반환합니다. 소비할 때마다 카운터, predicate 상태, 버퍼를 새로 만듭니다. 조기 종료나 예외 이후에도 같으며, 지연 콜백과 예외는 소비 시점에 실행되고 소비 사이의 변경은 다음 순회에 반영됩니다.

## Iterable 원본과 키 identity

`createQuerySequence(factory, options?)`는
`Iterable<readonly [string, T]>`를 만드는 factory로 지연 시퀀스를 생성합니다.
생성 시점에는 factory를 호출하지 않고, 소비할 때마다 다시 호출합니다.
새 iterator나 반복 가능한 iterable을 반환하세요. 이미 소진한 generator를
재사용하지 않으며 결과 캐시나 자동 되감기도 제공하지 않습니다.

```ts
import { createQuerySequence, iterateEntries, iterateValues } from "@ilokesto/queryable";

const rows = new Map([["2", 20], ["1", 10]]);
const query = createQuerySequence(() => rows.entries());
const entries = iterateEntries(query); // 아직 소비하지 않음
[...entries]; // [["2", 20], ["1", 10]]
rows.set("2", 30);
[...iterateValues(query)]; // [30, 10]
```

`iterateEntries(query)`와 `iterateValues(query)`는 배열을 먼저 만들지 않고
레코드와 시퀀스를 연결합니다. 각 iterator는 독립적입니다. entry 뷰의 새 튜플을
수정해도 버퍼링된 쿼리는 바뀌지 않지만, 값 자체는 얕은 참조입니다.
쿼리 자체의 기본 iterator 대신 entry와 value 중 하나를 명시적으로 고릅니다.

외부 entry는 문자열 키를 가진 길이 2의 배열이어야 합니다. `undefined`, Symbol,
opaque 객체를 포함한 값은 검사하지 않습니다. 잘못된 entry는 읽는 시점에
`TypeError`를 던집니다. 조기 종료와 downstream 예외는 획득한 generator를
닫으며, `LIMIT(0)`은 원본을 획득하지 않습니다.

`duplicateKeys` 옵션으로 키 충돌을 명시합니다.

| 정책 | 동작 |
| --- | --- |
| `"error"` (기본값) | 중복 entry를 읽으면 `DuplicateKeyError`를 던지며 `key`에 충돌한 키가 있음 |
| `"first"` | 저장된 `undefined`도 포함하여 첫 값을 유지하고 이후 중복은 건너뜀 |
| `"last"` | 전체 원본을 소비한 뒤 각 키의 첫 위치를 유지하며 마지막 값을 출력 |

identity 상태는 매 소비마다 새로 만듭니다. streaming 정책은 관찰한 키의 Set을,
`"last"`는 모든 고유 키의 Map을 보관합니다. prefix 소비는 실제 읽은 부분만
검증하므로 뒤쪽까지 고유하다고 보증하지 않습니다. 전체 소비는 기본적으로
중복 키를 조용히 덮어쓰지 않고 거부합니다. PICK·그룹·정렬·컬렉션 출력도
이 고유 키 경계를 사용하며, 이후 다중 원본 연산의 공통 identity 계약이 됩니다.
`TO_OBJECT`는 계속 숫자 키에 네이티브 객체 열거 순서를 적용합니다.

## 계층 탐색

`query[BFS](children, resultKey, options?)`와
`query[DFS](children, resultKey, options?)`는 즉시 평가 레코드에서도 항상
지연·정렬 시퀀스 `QuerySequence<TraversalNode<T>>`를 반환합니다.
두 selector는 `(value, context)`를 받습니다. children selector는 형제 순서의
`Iterable<readonly [string, T]>`를 반환하며, 호출마다 새 iterator나 반복 가능한
iterable을 제공해야 합니다. 지역 키는 전체 트리에서 고유할 필요가 없습니다.
필수 결과 키 selector가 생성된 행의 출력 identity를 정하며 공통
`duplicateKeys: "error" | "first" | "last"` 경계를 그대로 적용합니다.
`"first"`로 출력에서 제외한 행도 자식을 확장하므로 충돌 정책은 가지치기가 아닙니다.

```ts
import { createQueryable, BFS, DFS, MAP, VALUES } from "@ilokesto/queryable";
import type { TraversalContext } from "@ilokesto/queryable";

interface Node {
  name: string;
  children: ReadonlyArray<readonly [string, Node]>;
}
const query = createQueryable<Node>({
  root: {
    name: "root",
    children: [
      ["left", { name: "left", children: [["leaf", { name: "leaf", children: [] }]] }],
      ["right", { name: "right", children: [] }],
    ],
  },
});
const children = (node: Node) => node.children;
const key = (_node: Node, context: TraversalContext<Node>) => JSON.stringify(context.path);
query[BFS](children, key)[MAP](row => row.value.name)[VALUES]();
// ["root", "left", "right", "leaf"]
query[DFS](children, key)[MAP](row => row.value.name)[VALUES]();
// ["root", "left", "leaf", "right"]
```

각 행은 `value`와 selector에 전달한 문맥을 포함합니다. `key`는 원래 지역 입력 키,
`root`는 원본 root 값, `rootKey`는 root 입력 키, `path`는 root 키를 포함한 지역 키
경로이며 root의 `depth`는 0입니다. 출력 키를 바꿔도 이 문맥은 유지합니다.
값과 root는 얕은 참조이며 identity를 추측하기 위해 payload를 검사하지 않습니다.
`path`는 읽을 때마다 readonly 타입의 새 배열을 반환합니다. 내부에는 연결된 경로만
저장하므로 요청하지 않은 전체 경로를 깊은 트리의 모든 노드에 복사하지 않습니다.
모든 경로를 출력하면 이차 공간이 필요할 수 있습니다.

BFS는 모든 root를 먼저 출력한 뒤 root·자식 iterable 순서대로 각 깊이를 탐색합니다.
반복형 queue가 frontier의 자식 iterator를 보관합니다. DFS는 반복형 iterator stack으로
전위 탐색하며 한 root의 자손을 끝낸 뒤 다음 root를 읽습니다. 활성 stack 크기는 깊이에
비례합니다. 둘 다 재귀 호출이나 형제 순서 뒤집기를 사용하지 않습니다. BFS는 현재
깊이가 유한해야 다음 깊이에 도달하고, DFS의 무한 가지는 이후 형제·root 탐색을 막습니다.

`maxDepth`는 포함 경계이며 기본값은 `Infinity`입니다. 그 외에는 비음수 안전 정수만
허용합니다. 잘못된 값은 iterator 획득 전 연산 생성 시점에 `RangeError`를 던집니다.
0이면 root만 출력하며 경계 깊이의 노드는 children selector를 호출하지 않습니다.

`visitIdentity`가 없으면 같은 참조라도 각 경로를 별도로 방문합니다. cycle은 유한한
깊이 경계나 prefix 소비로 종료해야 합니다. `visitIdentity(value, context)`를 지정하면
소비마다 모든 root에 걸친 새 SameValueZero Set을 만듭니다. 탐색 순서상 첫 identity를
유지하며 이후 반복은 출력·자식 확장 모두 건너뜁니다. 참조 identity에는
`visitIdentity: value => value`를, 도메인 identity에는 ID selector를 사용하세요.
방문 identity와 출력 키 충돌은 별개의 정책입니다.

연산 생성과 `LIMIT(0)`은 root를 획득하거나 selector를 실행하지 않습니다.
노드를 먼저 출력한 뒤 자식을 선택하므로 prefix 소비의 마지막 노드는 확장하지 않습니다.
조기 종료와 selector·자식 iterator·downstream 예외는 아직 획득 중인 탐색 iterator를
모두 닫으며, 하나의 return이 실패해도 나머지를 시도합니다. 탐색 예외는 cleanup 예외보다
우선하고, 정상적인 조기 종료 중 cleanup이 실패하면 첫 cleanup 예외를 전달합니다.
자연 소진한 iterator의 `return()`은 호출하지 않습니다. 재소비마다 queue·stack·방문 상태·출력
키 상태를 새로 만들고 live 원본을 다시 읽습니다. `"last"`는 첫 결과 전에 전체 탐색을
버퍼링하므로 무한 탐색을 단축하지 못합니다.
## 인덱스 조인

`GROUP_JOIN(inner, outerKey, innerKey, project)`은 outer 키마다 결과를 하나씩
유지합니다. `project(value, matches, outerKey)`의 matches는 새 배열이며
readonly `[innerKey, innerValue]` 튜플을 담습니다. 일치하지 않으면 빈 배열입니다.
레코드 receiver는 레코드를, 시퀀스 receiver는 시퀀스를 반환합니다.

`INNER_JOIN`과 `LEFT_JOIN`은 같은 앞의 세 인자 다음에
`project(value, match, outerKey)`와 선택적 `{ duplicateKeys }`를 받습니다.
projection은 호출자가 정한 문자열 키의 **`[generatedKey, result]`를 반드시
반환**하며, 결과는 순서 있는 시퀀스입니다. 일치 context는
`{ matched: true, key: string, value: I }`입니다. LEFT_JOIN은 불일치 outer에
`{ matched: false }`를 한 번 전달하므로 저장된 `undefined`와 부재를 구분합니다.
INNER_JOIN은 불일치 outer를 출력하지 않습니다. 빈 outer에서는 결과가 없고
outer selector와 projection도 호출하지 않습니다. selector는 각 소스의
`(value, originalKey)`를 받으며 후속 콜백에는 명시적으로 생성한 키를 전달합니다.

```ts
import {
  createQueryable, GROUP_JOIN, INNER_JOIN, LEFT_JOIN, LAZY, VALUES,
} from "@ilokesto/queryable";

const users = createQueryable({ alice: 1, bob: 2 });
const orders = createQueryable({ first: { user: 1, total: 10 }, second: { user: 1, total: 20 } });
users[GROUP_JOIN](orders, id => id, order => order.user,
  (_id, matches) => matches.length)[VALUES](); // [2, 0]
users[LAZY]()[INNER_JOIN](orders, id => id, order => order.user,
  (_id, match, key) => [`${key}/${match.key}`, match.value.total])[VALUES](); // [10, 20]
users[LEFT_JOIN](orders, id => id, order => order.user,
  (_id, match, key) => [match.matched ? `${key}/${match.key}` : key,
    match.matched ? match.value.total : undefined])[VALUES](); // [10, 20, undefined]
```

조인 키는 native Map SameValueZero를 따릅니다. `NaN`끼리와 두 부호의 0이
일치하며 객체와 Symbol은 문자열 변환 없이 identity로 비교합니다. SORT를 포함한
outer 순서를 유지하고 각 outer 안에서는 inner 원본 순서로 출력합니다.
생성 키는 `createQuerySequence`의 공통 identity 경계를 통과합니다. 기본
`"error"`는 중복에서 예외를 던지고 `"first"`는 첫 값을 유지합니다.
`"last"`는 생성 entry 전체를 버퍼링하여 각 키의 첫 위치에 마지막 값을 둡니다.
특수 문자열 키도 일반 데이터이며 암묵적인 번호 생성이나 덮어쓰기는 없습니다.
streaming 정책의 prefix 소비는 실제 읽은 생성 키까지만 검증합니다.

소비마다 **inner 전체를 새 Map의 match 배열로 인덱싱**합니다. 메모리는
O(inner 항목 수)와 고유 조인 키 bucket에 비례합니다. outer가 비어도 inner를
끝까지 소비하고 항목마다 selector를 한 번 호출한 뒤 outer iterator를 획득합니다.
읽은 outer 항목마다 selector를 한 번, GROUP_JOIN은 outer마다 projection을
한 번, INNER_JOIN은 일치 pair마다, LEFT_JOIN은 pair 또는 불일치 outer마다
한 번 호출합니다. GROUP_JOIN은 projection마다 match 튜플을 복사합니다.
N:M에서는 출력이 outer 개수와 inner 개수의 곱까지 늘 수 있으며 즉시 평가
결과는 출력 전체를 저장합니다. identity 검증도 생성 키를 보관하고 `"last"`는
전체 결과를 저장합니다. 무한한 inner 원본에서는 결과를 출력할 수 없습니다.

레코드와 즉시 정렬 receiver는 호출 즉시 실행하고 지연 receiver는 demand까지
인덱싱과 콜백을 미룹니다. 지연 조인 뒤의 `LIMIT(0)`은 두 소스를 획득하지
않습니다. 인덱싱 이후 streaming 정책은 outer 조기 종료를 지원하고 획득한
iterator를 닫습니다. 소스와 콜백 예외는 그대로 전파하며 활성 iterator를
닫습니다. 반복·교차 지연 소비는 독립적인 인덱스를 만들고 소스 변경을 읽습니다.
즉시 평가 결과는 스냅샷입니다. GROUP_JOIN은 receiver 모드를 따르며 기존
GROUP_BY의 즉시 평가 의미는 바꾸지 않습니다.
## Selector 기반 집합

`DIFFERENCE`, `INTERSECTION`, `UNION`은 우측 쿼리와 필수 selector 두 개를
받습니다. `leftSelector(leftValue, originalKey)`와
`rightSelector(rightValue, originalKey)`의 값 타입은 달라도 되지만 반환하는
identity 타입은 같습니다. 비교는 JavaScript Set의 SameValueZero입니다.
`NaN`끼리, 부호가 다른 0끼리는 같고 `undefined`도 정상 identity입니다.
객체는 필드가 아니라 참조로 비교합니다. selector가 명시적으로 반환하지
않으면 레코드 키는 membership identity가 아닙니다.

| 연산 | 결과 |
| --- | --- |
| `[DIFFERENCE](right, leftSelector, rightSelector)` | 우측에 없는 identity별 첫 좌측 원본 entry |
| `[INTERSECTION](right, leftSelector, rightSelector)` | 우측에 있는 identity별 첫 좌측 원본 entry |
| `[UNION](right, leftSelector, rightSelector, options?)` | 좌측 다음 우측 순서로 identity별 첫 원본 entry; 값 타입은 `T \| U` |

세 연산은 수학적 집합입니다. multiset이나 중복을 유지하는 membership 필터가
아니므로 양측의 중복 identity가 결과 개수를 늘리지 않습니다. 첫 해당 entry의
원래 키와 값 참조를 유지합니다. receiver 모드도 유지하여 레코드는 네이티브
객체 키 순서의 레코드, 정렬·지연 시퀀스는 시퀀스를 반환합니다. 우측 쿼리의
모드가 receiver의 실행 시점을 바꾸지는 않습니다.

```ts
import {
  createQueryable, DIFFERENCE, INTERSECTION, UNION, ENTRIES,
} from "@ilokesto/queryable";

const left = createQueryable({
  a: { id: 1, label: "first" },
  b: { id: 1, label: "duplicate" },
  c: { id: 2, label: "second" },
});
const right = createQueryable({ r: { code: 2 }, s: { code: 3 } });
left[DIFFERENCE](right, row => row.id, row => row.code)[ENTRIES]();
// [["a", { id: 1, label: "first" }]]
left[INTERSECTION](right, row => row.id, row => row.code)[ENTRIES]();
// [["c", { id: 2, label: "second" }]]
left[UNION](right, row => row.id, row => row.code)[ENTRIES]();
// a, c, s: 우측 { code: 3 }을 포함한 원본 값
```

`UNION`은 값 identity 중복을 먼저 제거한 다음 결과 레코드 키 충돌을 처리합니다.
키가 달라도 identity가 같으면 하나만 남습니다. identity가 다르지만 키가 같으면
`createQuerySequence`와 동일한 `options.duplicateKeys`의 `"error"`(기본값),
`"first"`, `"last"` 정책을 적용합니다. 기본 충돌은 `DuplicateKeyError`를 던지고,
`"first"`는 첫 값, `"last"`는 키의 첫 위치에서 마지막 값을 유지합니다.
저장된 `undefined`도 정상 값입니다. 키 정책이 이미 identity 중복으로 제거한
entry를 되살리지는 않으므로 서로 다른 identity도 키 정책으로 탈락할 수
있습니다. `ENTRIES`, `TO_OBJECT`, `PICK`은 모두 같은 고유 키 결과를 받습니다.
각 입력의 원본 키 정책은 집합 selector보다 먼저 실행됩니다.

```ts
const a = createQueryable({ shared: 1 });
const b = createQueryable({ shared: 2 });
// a[UNION](b, n => n, n => n); // 다른 identity가 "shared"를 공유하여 예외
a[UNION](b, n => n, n => n, { duplicateKeys: "first" })[ENTRIES]();
// [["shared", 1]]
a[UNION](b, n => n, n => n, { duplicateKeys: "last" })[ENTRIES]();
// [["shared", 2]]
```

`DIFFERENCE`와 `INTERSECTION`은 좌측을 읽기 전에 우측 전체를 membership Set으로
버퍼링하며 좌측이 비어 있어도 같습니다. 우측은 유한해야 합니다. 이후 좌측을
streaming하고 출력한 identity의 Set을 보관합니다. 실제 방문한 entry마다
selector를 한 번 호출하며 우측 selector 전체 다음 좌측 selector 순서입니다.
`UNION`은 좌측 다음 우측을 streaming하면서 방문한 entry마다 selector를 한 번
호출하고 관찰한 identity Set을 유지합니다. 결과 키 정책 `"last"`는 추가로
모든 후보 결과 키를 버퍼링한 뒤 첫 항목을 출력합니다.

빈 입력은 해당하는 빈 집합 또는 남은 쪽의 고유 집합을 만들며 빈 쪽 selector는
호출하지 않습니다. 즉시 평가 연산은 호출 시점, 지연 연산은 소비 시점에
실행합니다. 지연 결과의 `LIMIT(0)`은 양측을 모두 읽지 않습니다. 조기 종단은
좌측 membership 순회나 streaming 합집합을 멈추지만 우측 membership 또는
`"last"` 키 버퍼링은 생략하지 않습니다. 조기 종료나 예외는 획득한 iterator를
닫으며 오류는 그대로 전파합니다. 지연 소비마다 membership, identity, 키 상태를
새로 만들고 메모이제이션하지 않습니다. 예외·조기 종료 뒤에도 같으며 살아 있는
쿼리 레코드와 반복 가능한 원본 factory의 변경은 다음 소비에 반영됩니다.
## 함수형 조합

소문자 adapter는 receiver를 유지하며 기존 Symbol 메서드를 호출합니다.
`where`와 `find`도 핵심 메서드의 Boolean·리터럴 false narrowing overload를 유지합니다.
`where(predicate)`, `map(mapper)`, `limit(n)`, `pick(...keys)`,
`sort(comparator)`는 데이터를 나중에 받는 unary stage이며 `lazy` 자체도
unary stage입니다. `where`는 타입 가드로 값을 좁히고 `map`은 값 타입을
바꿉니다. `sort`와 `lazy`는 레코드를 시퀀스로 전환하며 다른 변환은 입력
모드를 유지합니다. `pick`은 값 내부 필드가 아닌 레코드 키 전체를 고릅니다.

```ts
import {
  compose, createQueryable, lazy, limit, map, pipe, sort, values, where,
} from "@ilokesto/queryable";

const source = createQueryable<string | number>({ a: "one", b: 2, c: "three" });
const strings = where((value: string | number) => typeof value === "string");
const lengths = pipe(source, strings, map((value: string) => value.length));
// Queryable<number>; 콜백은 원래 key도 받을 수 있습니다.
const ordered = pipe(lengths, sort((a: number, b) => b - a), values);
// number[]: [5, 3]

// compose는 입력 타입을 정하고 왼쪽부터 실행하는 재사용 transform을 만듭니다.
const firstLength = compose<typeof source>()(strings, map((s: string) => s.length), limit(1), values);
firstLength(source); // [3]
firstLength(createQueryable({ other: "four" })); // [4]

const live = pipe(source, lazy, strings);
values(live); // ["one", "three"]
source.a = "changed";
values(live); // ["changed", "three"]; 메모이제이션 없음
```

`pipe(input, ...stages)`는 왼쪽부터 실행하며 `compose<Input>()(...stages)`도
같은 순서의 재사용 transform을 만듭니다. 명시적 입력 타입으로 원본 인스턴스
없이도 레코드·시퀀스 모드를 포함한 추론을 시작합니다. 둘 다 **타입이 있는 unary stage
1개부터 4개까지** 지원하며 타입을 지우는 초과 overload는 없습니다.
더 긴 쿼리는 pipe 또는 compose를 중첩하세요. 작은 고정 overload 집합으로
추론 비용을 제한하며 대량 overload를 가져오지 않습니다. adapter를 만들 때
원본이 없다면 재사용 콜백의 입력 타입을 명시하세요. terminal이 만든 배열이나
스칼라 뒤를 포함하여 모든 단계에 일반 unary 함수를 넣을 수 있습니다.

`values`, `entries`, `toObject`, `count`, `first`는 unary terminal입니다.
`find(predicate)`, `some(predicate)`, `reduce(reducer, initial)`도 데이터를
나중에 받는 terminal stage이며 `find`는 타입 가드의 좁힘을 유지합니다.
`reduce`는 호출마다 같은 명시적 초기값을 전달하므로 불변 reducer를 사용하거나
수정 가능한 누산기라면 stage를 새로 만드세요.

새 엔진, 인스턴스별 bound 메서드, 공유 cursor, 캐시는 추가하지 않습니다.
매 호출은 전달받은 쿼리에 위임합니다. 즉시·지연 평가 콜백 시점, opaque 값의
얕은 참조, 네이티브 레코드 순서, 시퀀스 순서, 버퍼링, 조기 종료, 던진 값
자체는 기존과 같습니다. 지연 소비는 매번 처음부터 실행하여 live 원본을 읽으며,
콜백과 명시적 누산기 객체는 호출자가 소유합니다.

## 읽기 전용 shape 스냅샷

`createShapeQueryable(input, keys)`는 키마다 값 타입이 다른 레코드를 위한
선택적 즉시 평가 `ShapeQueryable<S>` 뷰입니다. 문자열 키 목록은 필수입니다.
TypeScript 객체 타입은 열린 구조이므로 `{ count: number }`로 선언한 객체에도
다른 런타임 속성이 있을 수 있습니다. 요청한 키 중 자기 소유의 열거 가능한
문자열 키만 원본의 네이티브 객체 순서로 복사하고 중복 요청은 무시합니다.
숫자형 키도 `"2"`처럼 문자열로 선언하고 전달하세요. Symbol 키는 포함하지 않습니다.

```ts
import { createShapeQueryable, ENTRIES, PICK, MAP, WHERE, TO_OBJECT } from "@ilokesto/queryable";

const input: { count: number; label: string; optional?: boolean } = {
  count: 1, label: "one",
};
const snapshot = createShapeQueryable(input, ["count", "label", "optional"]);
for (const [key, value] of snapshot[ENTRIES]()) {
  if (key === "count") value.toFixed(); // number
  if (key === "label") value.toUpperCase(); // string
}
snapshot[PICK]("optional")[TO_OBJECT](); // {}; optional은 boolean | undefined
snapshot[PICK]("unknown")[ENTRIES](); // []; 원소 타입은 never
snapshot[MAP](String)[PICK]("count")[TO_OBJECT](); // { count: "1" }
snapshot[WHERE](value => typeof value === "number")[TO_OBJECT](); // { count: 1 }
```

뷰는 공유되고 동결된 Symbol 메서드 `COUNT`, `FIRST`, `VALUES`, `ENTRIES`,
`TO_OBJECT`, `PICK`, `MAP`, `WHERE`를 제공하며 직접 조회하는 레코드 속성은
없습니다. `MAP`과 `WHERE`는 레코드 순서대로 `(value, originalKey)`를 받아 즉시
실행하고 콜백의 예외를 그대로 전달합니다. `PICK`은 숫자 키의 네이티브 순서를
적용하면서 인자 순서로 선택하며, 없는 키와 중복 키는 무시하고 저장된 `undefined`는
유지합니다. 빈 입력에서는 콜백을 호출하지 않으며 개수는 0, 첫 값은 `undefined`,
컨테이너는 빈 결과입니다.

스냅샷과 추출한 배열·튜플·일반 객체는 얕게 동결됩니다. terminal은 새 컨테이너를
만들며 `ENTRIES`는 이미 동결된 튜플을 공유할 수 있습니다. 입력 객체와 중첩 값은
**동결하지 않습니다**. 입력 속성을 교체하거나 삭제해도 스냅샷은 바뀌지 않지만
중첩 객체는 참조를 공유합니다. 메서드는 receiver가 필요하며 중첩 값을 복제하거나
깊은 readonly 타입으로 바꾸지 않습니다.

객체 출력의 모든 속성은 입력에서 필수였더라도 optional입니다. 정적 타입은 자기
소유의 열거 가능한 속성임을 증명하지 못하기 때문입니다. `FIRST`에는 항상
`undefined`가 포함되며 어떤 체인도 nonempty를 보장하지 않습니다. bounded `PICK`은
요청한 키와 기존 키 범위의 교집합만 남깁니다. 일반 `string` 요청은 원래 가능한
키 범위를 유지하지만 임의의 새 키나 실제 존재 여부를 보장하지 않습니다.
optional 값에는 `undefined` 가능성도 남습니다. 저장된 `undefined`와 부재는
`COUNT` 또는 own-property 검사로 구분하세요.

`ShapeQueryable<S>`는 초기 객체 shape를 표현하고, 체인 결과는 공개 타입
`ShapeSnapshot<E>`를 사용합니다. `E`는 가능한 entry 튜플 union입니다.
`ENTRIES`는 키와 값이 연결된 튜플 union을 유지합니다. `MAP`은 키 범위를
유지하면서 콜백에서 추론한 결과 타입을 가능한 모든 키에 적용하며 키마다 별개의
반환 타입을 추론한 것처럼 취급하지 않습니다. `WHERE` 타입 가드는 기존 키별
값 타입과 가드 타입의 교집합을 남기므로 넓은 값 타입에 적용한 리터럴 가드도
지원합니다. boolean predicate는 가능한 값 타입을 유지하며 어떤 키든 제거할 수
있습니다. 콜백 인자는 값과 키의 union이므로 키 검사에 따른 제어 흐름 narrowing이
필요하면 `ENTRIES`를 사용하세요.

수정 가능한 `Queryable<T>` API는 바뀌지 않습니다. 다른 기존 연산이 필요하면
`snapshot[TO_OBJECT]()`를 `createQueryable`에 전달하세요. 새 mutable 레코드가
만들어지며 닫힌 shape 보장은 의도적으로 사라집니다. 이 스냅샷은 메모이제이션을
추가하거나 기존의 live `LAZY` 계약을 바꾸지 않습니다.

## 여러 원본 결합

`CONCAT(sources, options?)`는 수신자 뒤에 배열 순서대로 쿼리를 연결하고 각 키를
유지합니다. 뒤쪽 원본은 그 첫 entry가 필요할 때만 획득합니다.
`FLAT_MAP(mapper, options?)`는 원본 순서대로 `mapper(value, originalKey)`를
호출하고 반환된 iterable을 모두 소비한 뒤 다음 원본 entry로 진행합니다.
mapper는 키 없는 값 대신 명시적인 `[stringKey, value]` 튜플을 출력합니다.
원본 키는 콜백 문맥에 유지되며 출력 키가 새 identity입니다. 값의 필드를
검사하거나 암묵적으로 키를 만들지 않습니다.

두 연산은 위 factory와 같은 `{ duplicateKeys: "error" | "first" | "last" }`
옵션과 공통 identity 경계를 사용합니다. 기본값은 ENTRIES·TO_OBJECT·PICK을
통한 소비에서도 충돌을 거부하며, `"last"`는 첫 출력 전에 전체를 버퍼링합니다.
입력 쿼리 자체의 identity 정책을 먼저 적용한 뒤 결합 결과 정책을 적용합니다.

`ZIP(...queries)`는 위치별 값을 이종 타입 튜플로 추론하며 수신자 키를 유지합니다.
매 행마다 수신자부터 인자를 왼쪽에서 오른쪽으로 읽고, 첫 종료 원본에서
전체를 끝냅니다. 마지막 회차에서 앞쪽 원본은 짝 없는 값을 하나 읽을 수 있지만
뒤쪽 원본은 읽지 않습니다. 수신자가 비어 있으면 뒤쪽 원본을 획득하지 않습니다.
인자가 없으면 길이 1 튜플을 출력합니다.

세 연산은 행 확장·결합을 표현하므로 항상 시퀀스를 반환하며 수신자의 실행 모드를
유지합니다. 레코드와 eager 정렬 시퀀스는 호출 즉시 계산하고, lazy 수신자는
소비까지 지연하며 live·repeatable·nonmemoized 상태로 매번 새 iterator를 획득합니다.
빈 확장은 entry가 없고 빈 입력에서는 mapper를 호출하지 않습니다. lazy 결과의
`LIMIT(0)`은 원본을 획득하지 않습니다. 정상 소진한 iterator에는 `return()`을
명시적으로 호출하지 않습니다. 최단 종료·조기 반환과 factory·next·콜백 예외 시
중첩 원본과 형제 원본을 포함한 아직 소진하지 않은 획득 iterator를 닫습니다.
정리 예외가 있어도 나머지 정리를 시도하고 원래 예외를 덮어쓰지 않습니다.
원래 예외가 없으면 첫 정리 예외를 전파합니다. entry와 ZIP 행 튜플은 새로 만들되
값 참조는 얕게 유지합니다.

```ts
import {
  createQueryable, CONCAT, ZIP, FLAT_MAP, LAZY, ENTRIES, VALUES,
} from "@ilokesto/queryable";

const left = createQueryable({ a: 1, b: 2 });
left[LAZY]()[CONCAT]([createQueryable({ c: 3 })])[VALUES](); // [1, 2, 3]
left[ZIP](createQueryable({ x: "one" }))[ENTRIES](); // [["a", [1, "one"]]]
left[FLAT_MAP]((value, key) => [
  [`${key}:original`, value],
  [`${key}:double`, value * 2],
])[ENTRIES](); // [["a:original", 1], ["a:double", 2], ["b:original", 2], ["b:double", 4]]
```

## 로컬 entry 버퍼와 인접 그룹

아래 shared Symbol 메서드는 순서를 유지하는 `QuerySequence`를 반환합니다.
결과 키는 각 버퍼에 포함된 첫 entry의 원본 키인 anchor입니다. 생성한 인덱스나
selector 결과를 키로 쓰지 않으므로, 입력 키가 고유하면 숫자·특수 키를 포함한
anchor도 고유합니다. 값은 원본 `[key, value]`를 담은 새 배열이며 튜플도 새로
복사합니다. 중첩 값의 참조는 유지합니다. 겹친 window끼리 노출 튜플을 공유하지
않습니다. 다음 소비가 이전 버퍼를 변경하지 않으며, 노출 배열을 수정해도 즉시
평가 스냅샷이나 다음 소비 결과는 바뀌지 않습니다.

| 메서드 | 버퍼 정책 |
| --- | --- |
| `[CHUNK](size)` | 겹치지 않는 묶음; 마지막 비어 있지 않은 부분 chunk 포함 |
| `[WINDOW](size, stride = 1, partial = false)` | `0, stride, 2 * stride, ...` 위치에서 시작; stride가 작으면 겹치고 크면 간격을 건너뜀; 기본은 완전한 window만 출력 |
| `[PAIRWISE]()` | 완전한 인접 쌍만 출력; `EntryPair<T>`는 정확히 `[[string, T], [string, T]]` |
| `[SPLIT]((value, originalKey) => boolean)` | 일치한 entry는 구분자로 제외; 앞·연속·뒤 구분자는 빈 그룹을 만들지 않음 |
| `[PARTITION_BY]((value, originalKey) => selected)` | selector 결과가 같은 연속 구간을 출력; 마지막 비어 있지 않은 구간 포함 |

size와 stride는 양의 유한 정수여야 합니다. 잘못된 인자는 빈 입력이나 지연
쿼리에서도 원본 획득 전에 즉시 `RangeError`를 던집니다. 빈 입력은 버퍼를
만들지 않습니다. 짧은 입력은 부분 CHUNK를 만들지만 기본 WINDOW와 PAIRWISE는
만들지 않습니다. WINDOW의 partial을 true로 지정하면 끝 전의 모든 시작
위치에서 비어 있지 않은 부분 window를 만들므로, 겹치는 짧은 꼬리가 여러 개
나올 수 있습니다.

```ts
import {
  createQueryable, LAZY, CHUNK, WINDOW, PAIRWISE, SPLIT, PARTITION_BY, ENTRIES, VALUES,
} from "@ilokesto/queryable";

const query = createQueryable({ a: 1, b: 1, c: 2, d: 1 });
query[CHUNK](3)[ENTRIES]();
// [["a", [["a", 1], ["b", 1], ["c", 2]]], ["d", [["d", 1]]]]
query[WINDOW](2, 3, true)[VALUES]();
// [[["a", 1], ["b", 1]], [["d", 1]]]
query[PAIRWISE]()[VALUES](); // 원본 entry의 완전한 인접 쌍 3개
query[LAZY]()[SPLIT](value => value === 2)[VALUES]();
// [[["a", 1], ["b", 1]], [["d", 1]]]
query[LAZY]()[PARTITION_BY](value => value)[VALUES]();
// [[["a", 1], ["b", 1]], [["c", 2]], [["d", 1]]]
```

PARTITION_BY는 Set 기반 DISTINCT_BY와 같은 SameValueZero 동등성을 사용합니다.
`NaN`끼리 같고 `-0`과 `0`도 같으며 객체와 Symbol은 identity로 비교합니다.
저장된 `undefined`나 selector의 `undefined` 결과는 초기화 전 상태가 아닌
일반 데이터입니다. `A,A,B,A`는 세 구간이 됩니다. 기존 GROUP_BY는 계속 같은
문자열 그룹 키 전체를 즉시 모읍니다.

레코드와 즉시 평가 시퀀스에서는 호출 즉시 실행하여 스냅샷을 만듭니다. LAZY
이후에는 실행을 미루고 매 소비마다 live 원본을 다시 읽으며 버퍼 상태를
독립 생성합니다. 메모이제이션은 없습니다. 콜백은 읽은 entry마다 원본 순서로
한 번씩 `(value, originalKey)`를 받습니다. SPLIT은 그룹을 끝내는 구분자까지
읽습니다. PARTITION_BY는 경계를 확인하려고 다음 구간의 첫 entry 하나를
미리 읽고 selector를 계산합니다. 그 entry를 다음 구간에 포함하며 selector를
다시 부르지 않습니다. 입력 종료에 추가 콜백은 없습니다. 조기 종료와 콜백·원본
예외는 획득한 upstream generator를 닫습니다. 예외는 그대로 전파하고 다음
소비는 새로 시작합니다.

지연 CHUNK/WINDOW 내부에는 최대 size개의 원본 entry를 유지하고 PAIRWISE는
직전 entry 하나를 유지합니다. 새 출력 복사본도 버퍼 크기에 비례하는 공간을
씁니다. SPLIT과 PARTITION_BY의 현재 그룹은 구분자·selector 변경·입력 종료가
없으면 무한히 커질 수 있으며, 무한히 이어지는 한 구간에서는 그룹을 출력할
수 없습니다. 이 범위는 upstream identity 추적·다른 버퍼링 연산·소비자가
보관한 결과를 제외합니다. 즉시 평가는 모든 결과 버퍼를 저장합니다.

### Async entry 원본과 Promise 정규화

`createAsyncQuerySequence(factory, options?)`는 항상 지연 실행하는 별도
`AsyncQuerySequence<Awaited<T>>`입니다. `AsyncEntrySourceFactory<T>`는
`Iterable<readonly [string, T]>`, `AsyncIterable<readonly [string, T]>`,
또는 둘 중 하나를 감싼 PromiseLike를 반환합니다. 생성과 체인 연산은 원본을
획득하지 않습니다. 소비할 때마다 factory를 다시 호출하므로 새 iterator나
반복 가능한 iterable을 반환하세요. `LAZY`도 live·repeatable·nonmemoized입니다.

```ts
import {
  createAsyncQuerySequence, iterateAsyncEntries, MAP, WHERE, LIMIT, VALUES, GROUP_BY,
} from "@ilokesto/queryable";

const rows = new Map([["2", Promise.resolve(20)], ["1", Promise.resolve(10)]]);
const query = createAsyncQuerySequence(() => rows.entries())
  [MAP](async (value, key) => ({ key, doubled: value * 2 }))
  [WHERE](async value => value.doubled >= 20);
const values = await query[LIMIT](1)[VALUES](); // [{ key: "2", doubled: 40 }]
for await (const [key, value] of iterateAsyncEntries(query)) {
  // 명시적 entry 뷰이며 break는 upstream을 닫음
}
const groups = await query[GROUP_BY](async value => value.doubled > 20 ? "high" : "low");
const high = await groups.high?.[VALUES]();
```

- 원본 값과 `MAP` 결과는 중첩 PromiseLike까지 의도적으로 await합니다.
  plain·Promise·mixed·`never`·`undefined` 타입은 `Awaited`로 추론합니다.
  Promise를 opaque 값으로 보관하지 않으므로 값의 `then` 속성을 읽을 수 있고,
  rejection은 전파합니다. 일반 값 객체 안의 속성을 재귀 순회하지는 않습니다.
  기존 동기 쿼리는 계속 Promise와 다른 값을 그대로 저장합니다.
- `MAP`, `WHERE`, `FIND`, `SOME`, `GROUP_BY` 콜백은 원본 순서대로
  `(awaitedValue, originalKey)`를 받습니다. predicate와 grouping 콜백도
  PromiseLike 결과를 반환할 수 있습니다. 콜백이 끝나야 다음 entry를 요청하며
  동시 실행이나 prefetch는 없습니다. 동기 타입 가드는 `WHERE`/`FIND`를 좁히지만
  async boolean predicate는 타입을 좁히지 않습니다.
- `COUNT`, `FIRST`, `VALUES`, `ENTRIES`, `FIND`, `SOME`은 명시적으로
  Promise를 반환합니다. 빈 결과는 각각 `0`, `undefined`, 새 빈 배열,
  새 빈 배열, `undefined`, `false`이며 콜백을 호출하지 않습니다.
  저장된 `undefined`는 여전히 하나의 entry입니다.
- `iterateAsyncEntries(query)`와 `iterateAsyncValues(query)`는 독립 커서와
  새 entry 튜플을 가진 명시적·반복 가능한 async iterable 뷰입니다. 쿼리 자체에는
  기본 iterator가 없습니다. 기존 Symbol을 쓰는 메서드를 하나의 동결된 async
  prototype에서 공유하며, 동기 prototype과는 분리합니다.
- `SORT`는 소비할 때 전체를 버퍼링하고 동기
  `(leftValue, rightValue) => number` comparator를 받습니다. 동점은 안정적으로
  유지하며 숫자·특수 키도 시퀀스 순서를 보존합니다. `LIMIT`은 유한 음수의
  버퍼링과 빈 limit의 원본 미획득을 포함해 `slice(0, n)` 의미를 유지합니다.
  `FIRST`, `FIND`, `SOME`, 양수 `LIMIT`은 조기 종료할 수 있습니다.
- `GROUP_BY`는 반환된 Promise를 await할 때가 아니라 호출할 때 소비를 시작합니다.
  await 완료 시 모든 grouping 콜백이 끝나며
  `Partial<Record<K, AsyncQuerySequence<T>>>` 스냅샷 그룹을 반환합니다.
  그룹을 다시 소비해도 원본이나 grouping 콜백을 다시 실행하지 않습니다.
  각 그룹 entry는 입력 순서를 유지합니다. null-prototype 그룹 레코드는 네이티브
  객체 키 순서를 따르며 `__proto__`/`constructor`도 안전하게 지원합니다.
  그룹에 추가하는 변환은 지연 async 연산입니다.
- `duplicateKeys: "error" | "first" | "last"`는 동기 factory와 같은 identity
  규칙 및 `DuplicateKeyError`를 사용합니다. `"first"`에서 나중에 버리는 중복도
  포함하여 실제 읽은 값은 모두 await합니다. `"last"`는 출력 전 전체를 버퍼링하고
  각 키의 첫 위치에 마지막 값을 둡니다. identity 상태는 매 소비마다 새로 만들고,
  prefix 소비는 실제 읽은 entry만 검사합니다.
- source protocol은 `next()` rejection, 값·콜백 rejection, 조기 종료 시
  획득했으나 소진하지 않은 iterator를 정확히 한 번 닫고, `return()` 완료까지
  기다린 뒤 결과를 확정합니다. 자연 소진에는 `return()`을 호출하지 않습니다.
  기존 실패가 있으면 cleanup도 실패하더라도 원래 실패 identity를 유지하고,
  기존 실패가 없으면 cleanup 실패로 terminal 또는 뷰를 reject합니다.
  factory 실패도 소비를 reject하며 다음 소비는 새 factory 호출로 시작합니다.
  자원을 해제하려면 원본에 `return()`을 구현해야 합니다. 취소·finalization hook·
  동시 실행·retry·event는 이번 async 기반에 포함하지 않습니다.

## 네이티브 컬렉션 출력과 Map 키 그룹

`KEYS()`는 쿼리 순서의 새로운 문자열 배열을, `TO_MAP()`은 원래 키와 얕은 값을
가진 새로운 `Map<string, T>`를 반환합니다. 저장된 `undefined`도 보존합니다.
`TO_SET()`은 첫 출현 순서와 네이티브 SameValueZero 동등성을 사용합니다.
`NaN`끼리, `-0`과 `0`은 같고 객체는 참조가 같아야 합니다. 모두 terminal이므로
지연 작업은 호출마다 다시 실행됩니다. 반환 컬렉션을 수정해도 원본은 바뀌지 않습니다.

`GROUP_BY_MAP((value, originalKey) => groupKey)`는 객체·Symbol·숫자·`undefined`
등 임의의 Map 키를 받습니다. entry마다 selector를 한 번 호출하며 지연 입력도
즉시 소비하여 독립 그룹을 만듭니다. Map의 그룹 순서는 각 키의 첫 출현 순서이고
그룹 멤버는 원래 키와 입력 순서를 유지합니다. 레코드 그룹은 네이티브 객체 순서,
정렬·지연 그룹은 시퀀스 순서를 따릅니다. 값은 계속 얕은 참조입니다.

```ts
import { createQueryable, GROUP_BY_MAP, KEYS, TO_MAP, TO_SET } from "@ilokesto/queryable";

const team = {};
const users = createQueryable({ alice: { team }, bob: { team } });
const groups = users[GROUP_BY_MAP](user => user.team);
groups.get(team)?.[KEYS](); // ["alice", "bob"]
users[TO_MAP]().get("alice"); // { team }
users[TO_SET]().size; // 2: 서로 다른 사용자 객체
```

그룹 키를 문자열이나 레코드 키로 바꾸지 않습니다. 반환 Map은 쿼리가 아니며
JSON·객체로 자동 변환하지 않으므로 직렬화 표현을 직접 선택해야 합니다.
기존 문자열 키 `GROUP_BY`는 유지합니다. 빈 입력은 새로운 빈 컬렉션을 반환하고,
factory 원본의 중복 키 정책은 연산 전에 적용되므로 기본 `TO_MAP`은 중복을
조용히 덮어쓰는 대신 오류를 냅니다.

## 비동기 취소와 수명 hook

`createAsyncQuerySequence`에 `{ signal }`을 전달합니다. factory는 그 signal을
받고, 비동기 `MAP`·`WHERE`·`FIND`·`SOME`·`GROUP_BY`와 동기 `SORT` 비교 함수는
기존 인자 뒤에서 받습니다. 설정하지 않으면 `undefined`이며 기존처럼 인자를
적게 받는 함수도 사용할 수 있습니다.

```ts
import { createAsyncQuerySequence, FINALIZE, MAP, ON_COMPLETE, VALUES } from "@ilokesto/queryable";

const controller = new AbortController();
const query = createAsyncQuerySequence(
  signal => [["a", signal?.aborted ? 0 : 1]],
  { signal: controller.signal },
)[MAP](async (value, key, signal) => value + key.length)
  [ON_COMPLETE](() => { console.log("upstream 완료"); })
  [FINALIZE](outcome => { console.log(outcome.reason); });
await query[VALUES](); // [2]
```

이미 취소된 signal은 factory를 획득하기 전에 정확한 `reason`으로 거부됩니다.
factory·`next`·값·callback의 대기 중에도 abort로 소비를 중단합니다. 각 대기가
끝나면 abort listener를 해제하고 외부 작업의 늦은 rejection도 처리합니다.
같은 취소 signal의 쿼리를 다시 소비해도 거부되므로 새 수명에는 새 controller와
쿼리를 만드세요.
버퍼링된 SORT·음수 LIMIT·`"last"` 충돌 결과와 스냅샷 그룹도 출력마다 취소를
확인하며, 비교 함수가 취소한 뒤에도 결과를 출력하지 않습니다.

소비 중단은 임의 외부 작업의 강제 취소가 아닙니다. 받은 signal을 외부 작업에도
전달해야 협력적으로 취소할 수 있습니다. abort하면 획득한 iterator의 `return()`
을 한 번 시도하되 비협력적인 pending `next()`가 큐를 해제하기까지 기다리지는
않습니다. 뒤늦은 정리 오류는 abort 원인을 바꾸지 않습니다. 다른 종료 경로는
iterator 정리를 기다립니다. 네이티브 async generator가 signal을 무시하는 외부
작업을 기다린다면 실제 정리는 나중에 끝날 수 있습니다.

`FINALIZE((outcome, signal) => ...)`는 시작된 소비마다 조기 종료·오류를 포함하여
한 번 실행하고 완료를 기다립니다. `ConsumptionOutcome`은 `"complete"`·`"return"`
또는 `error` 필드를 가진 `"error"`·`"abort"`입니다. hook의 upstream 단계를
설명하므로 downstream 오류는 return으로 닫히고 upstream 내부 오류만 error로
관찰합니다. 이 차이에 맞춰 hook을 배치하세요. 먼저 발생한 upstream 오류·abort는
finalizer 오류보다 우선하고, 기존 오류가 없으면 정리 오류로 소비가 거부됩니다.
finalizer가 끝나야 consumer도 끝납니다.

`ON_COMPLETE(callback)`은 자기 upstream의 정상 소진에서만 실행하며 조기 반환·
실패에서는 실행하지 않습니다. `LIMIT(1)` 뒤의 hook은 제한된 단계의 정상 완료를,
앞의 hook은 조기 반환을 봅니다. 미사용 쿼리와 downstream `LIMIT(0)`은 원본도
hook도 실행하지 않습니다. 메서드는 공유·동결하며 매 소비의 실행 상태는 독립적입니다.

## 모듈별 import와 번들 경계

ESM 전용 패키지는 기존 root와 두 개의 명시적인 subpath를 제공합니다.

| entry | export | 런타임 경계 |
| --- | --- | --- |
| `@ilokesto/queryable` | 기존 생성자·Symbol·어댑터·타입 전체 | 생성자는 전체 공유 prototype을 유지 |
| `@ilokesto/queryable/operators` | `compose`, `count`, `entries`, `find`, `first`, `lazy`, `limit`, `map`, `pick`, `pipe`, `reduce`, `some`, `sort`, `toObject`, `values`, `where` | 기존 동기 어댑터와 핵심 Symbol만 로드하며 root·비동기 구현은 import하지 않음 |
| `@ilokesto/queryable/symbols` | 모든 공개 연산 Symbol | 핵심·기능군 모듈의 단일 정의를 다시 export하며 쿼리 생성자는 포함하지 않음 |

```ts
import type { QuerySequence } from "@ilokesto/queryable";
import { map, pipe, values, where } from "@ilokesto/queryable/operators";
import { VALUES } from "@ilokesto/queryable/symbols";

export function doubled(query: QuerySequence<number>): number[] {
  return pipe(query, where((n: number) => n > 1), map((n: number) => n * 2), values);
}

export function read(query: QuerySequence<number>): number[] {
  return query[VALUES]();
}
```

이 소비자는 이미 만들어진 쿼리를 받습니다. root 생성자로 쿼리를 만들면 여전히
전체 공유 prototype 비용을 부담합니다. operator import를 선택해도 생성자와
체인을 함께 포함한 번들이 연산 하나의 크기로 줄지는 않습니다. 네이티브 ESM에서
`symbols` entry는 기능군 모듈도 로드하므로 Symbol마다 모듈 하나만 로드한다는
보장이 아닙니다. 번들러는 사용하지 않는 export를 제거할 수 있습니다.

하나의 해석된 패키지 인스턴스 안에서는 root와 subpath가 정확히 같은 Symbol과
어댑터 함수를 공유합니다. 레코드·시퀀스 메서드의 기존 공유 identity도 유지하며
import 순서에 영향을 받지 않습니다. 독립 번들 또는 별도 설치된 복사본은 별도
인스턴스이며 Symbol을 전역 registry에 등록하지 않습니다. `where`·`find`의
타입 가드·`Boolean`·리터럴 `false` narrowing과 기존 실행·버퍼링 규칙을 유지합니다.

각 공개 entry는 ESM과 declaration export 조건을 제공합니다. 쿼리 타입은 root에서
`import type`으로 가져오세요. `/functional`·`/core-symbols`·`/dist/index.js`·
`/operators/where` 같은 내부 경로는 공개 export가 아닙니다. 런타임 의존성은
없습니다. 생성자·terminal·operator·전체 체인의 실제 출력 크기와 import graph는
저장소의 `bench/modular-results.md`와 JSON artifact에서 확인할 수 있습니다.
`sideEffects: false` 설정만으로 소비 번들이 작아졌다고 판단하지 않습니다.
